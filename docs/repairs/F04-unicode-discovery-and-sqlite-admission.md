## 根因与修正

旧检索的查询侧用 Python casefold，资产侧却用仅支持 ASCII 的 SQLite lower；标签还被当作整个 JSON 字符串匹配。
原样查询 Straße、ÉTUDE 和部分希腊词会漏检，带引号标签也失配，序列化标点则会产生假命中。
现在用 SQLite 官方连接回调接口调用标准 Python casefold，先解析真实标签值，再对元数据和查询采用同一关系。
不增加手写 Unicode 表、分词器、向量服务、持久归一化列或索引维护分支。

检索仍在评分前选择每个 scope/name 家族的当前已采用头；候选、退役和版本规则保留。
前 16 个空白分隔词按字面子串 OR 匹配，分数累计命中词项，重复词保留重复权重；同分按名称、范围稳定排序。
实际结果上限与工具声明共用同一常量，越界参数在调用前拒绝，不扣调用额度。
标签只贡献真实值，不贡献 JSON 外层语法，正文不加入元数据检索。

原 Python 版本声明没有覆盖所用 SQLite 窗口函数前提。现在环境诊断和 Store 准入共用真实内存探针，
通过同一连接工厂执行物化 CTE、窗口查询、Unicode 回调正控，并启用、读回外键策略；失败安全关闭连接。
Store 在目录创建、改权限和持久开库前拒绝缺失能力；doctor 不创建任务数据。
不凭版本字符串推断支持，也不增加替代引擎、迁移或旧格式分支。存储表示不变，格式仍为 3。

## 验证结果与边界

首版 P1–P4、物化回边设计与最终实现 P4 均已独立技术核验通过；仅本批两项发现转为 verified，维护者终验保留。
首版主执行通过 101 项运行测试、12 项开发测试及完整开发门；修前、修后真实采用与查询结果分别保留。
独立首版矩阵 149 项与 6 项补检通过，先前两轮探针的错误预期已单独归因，不把它们写成产品缺陷。

一次诊断微基准确认查询词增多会重复解析和折叠元数据，因此返回 P2/P3 比较两个实作备选，重新独立核验后再实施。
在同机 2000 个直接播种的合成头上，N=3：16 词首版约 0.61–0.63 秒；物化投影约 0.045–0.052 秒；
本次四参数评分回调候选约 0.11–0.14 秒。后者带严格 JSON 词项解码，不代表所有可能的评分回调实现。
选择 SQLite 官方的 AS MATERIALIZED 投影：先选当前头和范围，再准备真实元数据，空查询不折叠；没有新增持久索引或缓存。
该额外 SQLite 能力也纳入同源探针，不提供旧引擎兼容分支。物化有临时内存/存储代价，局部成本实测不当作普遍速度保证。

最终主执行完整门通过 102 项运行测试、12 项开发测试，以及 pin/元数据、官方技能格式、Ruff、mypy、文档引用和增长预算检查。
最终同机夹具实测 16 词约 49–62 毫秒，2000 个头各调用一次折叠，空查询零次；不把这些样本外推成时延分布。
独立核验亲跑最终 156 项通用检查、13 项物化专项及 6 项组合补检，覆盖真采用、词项与范围、生命周期、坏标签隔离、
十类 SQLite 故障注入、新旧 home 保护、连接关闭、格式拒绝、实际存储错误和既有未知副作用保证。
成功通过内存准入后再发生的持久连接失败仍可能留下已获准目录；它按现有 storage_failed 边界处理，
不被误写成“任何后续 I/O 失败都不改目录”的保证。
