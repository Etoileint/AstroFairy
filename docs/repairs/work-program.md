# 整体复核与优化的当前工作范围

[工作状态数据](work-program.json)连接原综合复核和当前修复台账。它保留原检查、愿景、场景和对象的后续去向；
映射完整不等于这些对象已经通过。历史复核不追写，原有“有限支持”和“待证”不能因15项技术问题闭合而自动消失。

当前状态以 JSON 数据为准；下表解释各工作的责任，不复制可变的状态值。

| 工作 | 责任 | 完成依据 |
|---|---|---|
| P00 原15项问题 | 问题修复子台账 | [修复台账](status.json)，维护者终验仍独立 |
| P01 文档存储与选读 | 文档表示与读取机制 | 消除整份快照重复存储及片段读取的整份处理，验证完整性与新增成本 |
| P02 重放与数据寿命 | 历史与资产生命周期 | 历史重放、保留、备份恢复、退役与引用的边界及实测 |
| P03 质量与端到端成本 | 实际任务评测 | 真实模型任务、直接执行对照、用户等待和维护代价 |
| P04 安装与原生宿主 | 使用通道取证 | 安装前提、原生发现/调用、升级、平台与应用渲染分别取证 |
| P05 真实成员体验 | 现场证据；可先准备 | 成员的实际操作、审核理解和反馈，不能由模型扮演代签 |
| P06 学习与成熟工作流 | 复用与检索效果 | 复用的收益/成本/反例、任务查询的检索相关性与成熟方案比较，以及真实长期观察 |
| P07 规范、承诺与终验 | 汇总验收 | 修改影响域的权威对标、全量证据去向和维护者接受 |

原综合结论的前四组修复由 P00 承接，第五组“受限实际使用和持续观察”由 P03–P07 承接。
原 R07/R10 的速度与增长问题由 P01/P02/P03 分别承接；F07 新机制的存储放大明确属于 P01。
原安装说明、请求录入、证据取得和复核基础设施附注也保留，不因不在15项中而丢失。

P01/P02已按各自范围完成技术复验，状态和证据以JSON为准；接下来准备和运行P03/P04/P06的实际评测。
P05的准备无需等待，
但最终证据必须来自真实成员。P07 汇总各工作结果，不以任意一张绿色表或测试计数签整体完成。
未来长期效果采用明确样本与观察跨度，既不伪造跨年结果，也不要求等待无限时间才允许范围明确的试用。

执行 `python dev/check_work_program.py` 核对冻结来源身份、检查/愿景/场景/对象的映射、附注去向及证据路径。
该检查只核对工作范围与状态结构，不替代产品、模型或真人评测。当前产品整体未验收。
