# 再次定向返工要求

依据：[本轮独立复验](README.md)、[首轮返工](../acceptance-2026-11-08/rework.md)和既有ADR/验收矩阵。
已通过项保留，不重做无关架构；未闭合项按机制边界修复，不能继续只对最小报错点增加例外。
本清单不授予提交、推送、发布、Issue外部动作或兄弟仓写入权限。原会话仍负责独立复验。

## 规范轴

| ID | 必须完成的机制修复与反例 |
|---|---|
| STD01 | 工具选择、版本/身份探测、执行体摘要取得、真正compile执行使用同一环境/来源边界。禁止PYTHONPATH/CWD等未声明模块注入工具身份；保持真实uv污染环境下锁字节稳定。不能只隔离最后一次subprocess |
| STD02 | 更新前验证已有来源/清单/provenance；不能用update给未授权漂移重新盖章。校验所有保留来源，不只当前选中pin；明确处理合法新增/刷新所需的权威采购与旧清单校验顺序。漂移摘要、非法未选中来源及版本/URL错位在check和update都应红 |
| STD03 | 从固定消费者原件独立发现或绑定其真实完整消费义务，不能由可同步删改的consumes集合决定检验集合。保持源码/哈希不变、同时删四处config.json声明仍须拒绝；版本/源码变化触发重新审计，不另造通用Python分析器 |
| STD04 | 每个环境按包收集所有实际含包的profile并比较，不能用所有profile全交集。相同合法fork通过；A/B共享冲突包且C无该包仍拒绝；C加入不相关包不能关闭旧检查 |

## 方案轴

| ID | 必须完成的机制修复与反例 |
|---|---|
| SPEC01 | 安全遍历必须对不可读/不可遍历的子树fail-closed；不能让os.walk默认吞错误。真实非特权权限负例中，无法证明安全的旧树不移动、不跟随，外部目标不触碰；保留普通坏包可重建 |
| SPEC04 | 从已验staging开始到返回期间的安全检查、rename、发布后复核等共用完整进度错误边界。任意已发生动作后的失败都携回completed/published/quarantined/recovery；不能只包最后_verify |
| T29＋REG02 | 明确区分权威数据库提交、已提交invoked、外部效果、observed记录及交付投影。移除整方法_precommit的默认false推断；只在实际已知阶段断言。已知回滚为false，提交无法确认明确unknown；保留原始COMMIT错误，不能被ROLLBACK再失败遮蔽。invoked已记录/效果可能发生而观察入库失败时保留task/call/已知序号及安全调查动作，不能引导重放效果 |

T29的外部write.status=unknown不能充当权威COMMIT=unknown的测试；两者分别测试，不能在不同错误族里改变committed含义。
实现可在原有错误详情表达明确阶段/身份，不要求新增事实类型、跨数据库事务或外部exactly-once系统。
若需要改变既有契约语义，先交回具体设计决定，而不是以实现自行定义成功含义。

## 验证与回交

1. 回归包含本轮真实反例，同时保留已绿的SPEC02/SPEC03/GAP01/T35、STD05/STD06及规范轴已正确的子场景。
2. 原始脚本/输出保留；私有接口变化可适配场景，但不能用脚本不兼容宣称旧发现已关闭。
3. 完整检查、对应分发和真实模型验证按影响域执行；未执行的平台/host义务如实保留，不自行豁免。
4. 新候选、逐项处置和证据另建目录，不覆盖前两次回交或两轮验收。统一或显式登记所有证据路径的根；源码记录数区分现存与删除。
5. 明确列明源清单、分发制品、实际命令/环境/退出码、T映射、通过/失败/未执行；已发生数据库/文件动作的错误证据必须可复盘。

本轮证据脚本入口在维护者验收目录`standards/`的`probe.py`、`real-uv.py`、`tool-selection-probe.py`、
`consumer-effect-probe.py`，以及`spec/`的`probe.py`、`unsafe-walk-probe.py`、`invoke-progress-probe.py`。
具体命令和限界以对应独立报告为准。
