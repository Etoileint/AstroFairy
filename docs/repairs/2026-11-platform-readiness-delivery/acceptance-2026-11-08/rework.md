## Standards轴

| ID | 根因处理与完成条件 | 原规格/验证 |
|---|---|---|

| STD02 | 官方name/version→URL身份、原件SHA、完整来源清单摘要与provenance真正接线；所有读写/复用入口使用同一验证。URL改为非批准域、摘要漂移、源版本错位均应红，正常离线检查仍无需网络 | ADR §2，R02/R13，T03 |
| STD03 | 用受身份约束的固定上游消费者原件建立消费审定与重新审计门，不能让三份手写清单相互证明。假wheel摘要、同步删config、消费方版本/源码变化须拒绝或要求重新审计。避免另造通用Python源码分析器；保留六文件运行验证 | ADR §3，R04/R13，T10 |
| STD04 | 保留每个明确环境单元的选择，在同一环境内比较跨profile共同包；不能跨环境union后要求全局只有一版。相同合法fork通过，同环境真正冲突拒绝 | ADR §2，R01/R02，T01/T03 |
| STD05 | marker所需字段完整显式，或对无法表达的目标字段明确拒绝；不能由packaging补宿主默认。相同声明环境在任意宿主release/version下不静默变判定 | scope R01/R02，T01/T03 |

## Spec轴

| ID | 根因处理与完成条件 | 原规格/验证 |
|---|---|---|
| SPEC01 | 区分可重建的派生完整性问题与不可修复的安全/来源拒绝；unsafe祖先/root/后代始终拒绝，移动前再核旧树。普通坏包可repair；symlink/junction/reparse对象不移动、不跟随、不触外部目标 | ADR §4/§5，T14/T25 |
| SPEC02 | 在已知提交边界保留task/操作/call/child/committed_seq，不让SQLite等导出错误穿透为丢上下文的通用错误。覆盖close、晚到观察/反馈和learn；只恢复deliver，不重放业务动作 | ADR §5 Composition and errors，T17/T19/T20/T29 |
| SPEC03 | 选中导出快照时保存实际S，失败回包仍绑定该S；后续最新状态作为另一个观察。尚未选中时明确未知，不用重新读到的最新seq伪造失败目标 | ADR §5 Snapshot and concurrency，T22/T23/T29 |
| SPEC04 | 在修复全生命周期保存已发生动作及quarantine身份；隔离前、rename间、发布后/最终复核失败均回报准确进度和恢复。不得将失败说成未发布，或改成丢弃隔离物 | ADR §5 Missing, invalid and restored exports，T26 |
| GAP01 | 显式区分历史记录投影的“无live registry”和当前评估的“registry已知但checker缺失”；历史收据仍稳定可复用，当前检查/采用适用性不以缺失冒充通过 | ADR §5 Deterministic receipt inputs，T35 |

T29另须证明提交前失败为false、不确定提交为unknown；不能靠字段缺失表示二者，也不能假装恢复能撤销已提交事实。
T35须有固定输入事件/契约/内容与固定历史receipt期望值；同格式语义改变应能被该门捕获，不能只与当前实现自身输出互比。

## 回归与回交

1. 将独立反例变为能红/绿的所属测试，先观测旧实现红；原始脚本不得改成“已通过”来冒充原始结果。
2. 同时保留现有正向：普通合法交付复用、同seq并发、坏包保留隔离后重建、历史checker变化收据稳定、显式模型重新验证、来源离线检查。
3. 按影响域执行完整`dev/check.py`与相关分发/真实模型验证；跨平台等原有硬义务逐格记录，缺环境不得伪报或自行豁免。
4. 新回交包含完整源码/证据清单、SHA256、实际命令与环境、逐发现处置、逐T证据及未完成项。源与分发制品必须对应同一候选。
5. 不覆盖原实施回交或本轮证据；保留旧passed表，在新表中准确修正被反例推翻的条目。原会话复验，维护者最后裁定。

原证据脚本位于维护者验收目录的`standards/probe.py`、`standards/increment-probe.py`、`spec/reproduce.py`。
执行者可在新的隔离目录使用其场景，不依赖原会话上下文来理解报错。
