# 范围、需求与进入判据

日期：2026-11-08。对象：四条公开反馈涉及的依赖分发、检索准备、BagIt 边界和交付恢复契约。
本轮授权：调查后的正式方案、权威来源采购、独立设计检查与本仓文档留痕；不把方案授权解释成实现、外部发言、提交或发布授权。
这是维护者与 agent 的设计协作。独立验证者核验技术关口，维护者为最终裁决者；不得代签。

## 环境与威胁

- 基准使用 SQLite 权威事实、派生检索和可再生交付；协议/存储10，归档1。
- 已知参考环境为 Linux；Windows 用户报告是输入，原生 Windows 验证仍须执行。
- 环境变量、宿主平台、依赖元数据、文件路径、缺失/损坏模型、部分缓存、损坏或旧交付包均不可当作隐含成功依据。
- 包括进程中断、存储/权限失败、并发事件追加和重复恢复；保留当前完整性校验、权限及未知效果语义。
- 防止错误元数据、镜像/源身份漂移、冒充检验结果、路径逃逸、模型内容替换、交付包内部自洽但偏离权威记录。
- 不承诺对抗拥有任意写入权限的本机攻击者、零时延跨存储一致性、跨服务 exactly-once 或任意平台/未来解释器的无限兼容。

## 需求轴

| ID | 必须满足的结果 | 设计与验收落点 |
|---|---|---|
| R01 | 支持环境显式；依赖闭包和可安装制品不随生成宿主静默改变 | 依赖设计；目标环境安装与负例 |
| R02 | 用成熟解析/锁定实现，权威元数据和哈希可追溯；不再手写通用解析器 | 备选对照、锁再生、元数据身份与漂移检查 |
| R03 | 普通空库查询轻量；显式准备在无活跃资产时仍履行准备契约 | 准备设计；空库/候选库/非空库入口测试 |
| R04 | 依赖、模型验证和投影有效性分开表达；未知不能报告已验证 | 诊断接口；版本/缺失/损坏/旧投影用例 |
| R05 | BagIt 上游路径只在明确边界转换；分类与比较使用一致表示 | 路径适配；原生 Windows 与非法路径负例 |
| R06 | 内容验收、关闭事实、当前导出状态互不冒充 | 交付状态；close/next/deliver 全链 |
| R07 | 导出失败不抹掉已提交事实；错误和 next 提供安全恢复，重启后仍可接续 | 错误契约；首次/晚到事实/重复与中断测试 |
| R08 | 导出和校验绑定任务、快照、序号与内容；旧包、删除、损坏、恢复及并发不得误报 | 交付身份与完整性；失败矩阵 |
| R09 | 保留纯状态/事件职责和可重建投影；不引入无必要的双写真相、迁移或兼容分支 | 模块责任与替代方案审查 |
| R10 | doctor/next/inspect、普通空库查询及纯元数据浏览不下载或加载推理模型，不全量扫描交付包；已准备的非空语义检索允许必要推理；下载和完整校验必须显式、深度可知 | 成本与观测契约；调用探针、流式校验 |
| R11 | 同类入口统一修复：关闭、晚到观察/反馈、学习后序号变化、备份恢复、分发包与检查入口 | 消费者清单、端到端与分发测试 |
| R12 | 人只提交任务或回答必要问题；环境与恢复由 agent 有序完成 | Skill/host 指引、可执行恢复动作 |
| R13 | 独立复验、权威来源、执行证据、双向追溯和明确限界；旧证据保留原样 | 方案评审与实施验收记录 |

需求起点：四条 Issue 的实际症状、当前源码的相关调用链、既有架构保证、维护者持续约束。
按输入需求与实现消费者两路交叉检查；这是有界覆盖声明，不声称穷尽所有未知缺陷。

原生验证的最低必需环境是 Linux aarch64维护者通道、Linux x86_64现有CI参考通道与 Windows x64 / CPython 3.12通道。
Windows 11是用户报告环境；若采用托管Windows Server runner，必须如实记录OS版本，不冒称已在Windows 11复现；精确报告环境的缺口单列。
Python >=3.12 是运行最低版本声明，不是所有未来解释器/架构均经认证的证明。
方案必须区分解析目标、制品可用性和实际原生验证矩阵；其余环境须逐格登记证据，不能从通用 wheel 或 Linux 成功推定。
新增平台承诺或削减已有明确承诺均须维护者裁决。
