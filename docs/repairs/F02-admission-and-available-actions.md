## 根因与修正

| 发现 | 根因 | 机制修正 |
|---|---|---|
| R04-D01 | 分流后漏检或仅在动作前无锁预检序号 | 同源事务准入；检查在实际 invoked 前复核序号，学习读源与建子任务同事务 |

## 关键边界

检查批次固定最初的成果、发布序号和约定修订。首次 invoked 是有候选时的准入线性化点，后续调用沿用上一轮收口序号。
处理器在事务外执行；期间不改变目标的反馈可以纳入该轮收口，目标变化不能被重新选成新目标。批次不是全有或全无，
已发生的观察保留。空候选仍须检查前提。

学习请求在单一事务内读取源、保存快照并创建子任务，源记录不变；快照带源 task 和 seq。
同一当前序号再次请求可能得到不同子任务，expected_seq 是新鲜度前提，不是幂等令牌。
曾比较新增 learning_started 源事件，但它不是修复必要条件，故未增加。

配置错误在任务、工作区或附件 blob 创建前拒绝；CLI 还在打开 Workshop 前拒绝。Python 调用者此前可能已经初始化 home。
附件捕获和任务事件在同一数据库事务中，后续附件失败回滚先前 blob；本批不声称任意磁盘故障下文件系统与数据库跨资源原子。

数据库错误只返回固定消息及 SQLite 提供的 code/name（缺失则 null），不暴露 SQL、路径、材料或原异常文本，不重建数据库。
普通 Python API 仍抛数据库异常，版本拒绝和 argparse 用法错误各自保持明确契约。

预算零仍可处理已存在的结果、待答及纯语义审查；确需新机械检查时不会绕过预算。失败结论仍须有证据的显式替代，
未知副作用仍阻止 complete。next 的 publish_candidate 只是一个候选；inspect 可找其他输出，不自动判断候选质量。

工作包也只从一次事件快照生成，避免两次读取之间到达的新答复与旧 seq/revision 混用。
真实另一连接插入答复的回归在修正前失败、修正后通过。
