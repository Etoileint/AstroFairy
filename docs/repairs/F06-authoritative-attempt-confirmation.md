## 决定与机制

保守地阻断未知调用是正确底线；本批补充显式支持工具的同任务核对能力。写工具可声明受信的只读 reconciler，
实际效果前冻结其名字、完整定义与摘要；Context.call_id 把已持久化尝试的身份交给处理器。
调用核对工具使用普通 read 权限、预算和执行路径，以严格原 call 参数在观察前绑定目标。
核对需要能按原尝试取得权威终态，文件碰巧存在、参数相同或人的成功表述都不够。

符合原 writer 冻结结果模式、完整输出描述符及字节校验的正向 native 观察可建立确认。
当前确认和不可静默撤销的矛盾从 invoked/observed 重放派生，不新增第二接纳命令或重复事件，不覆写原来的未知结果。
精确 canonical 完整结果包含输出顺序、名字、类型、重复数量和额外字段；此严格 profile 不承诺识别全部业务语义等价。
普通大结果不因本批新增整体 16MiB 副本限制，结果摘要也不冒充可直接读取的 blob ref。

不同正向结果会留下持续争议，A→B→A 或 unknown 不能洗白；complete、后续采用及 next/inspect/回执都消费当前执行完整性。
核对不重放写操作，也永久阻断该已确认尝试的同 operation 重复执行。事实可跨旧 revision 核对，质量检查仍须当前 revision。
不支持核对、只得到非终态或资源缺席、预算不足时保留部分/失败/取消出口，不推断安全重试。

事实先提交，已关闭任务随后刷新回执；导出失败不回滚观察。导出自身在独立事务内取一个快照并与事件写入串行，
seq 表示该回执的历史快照。数据库与文件系统不承诺跨资源原子，已分发副本和已采用资产不会自动全局撤销。
协议和存储采用格式 4，不迁移旧库，不保留旧读分支；没有新增运行模块、工作流服务或第二执行体系。
