## 根因与职责

F07把每次回包限制住了，但变化后的文档仍整份保存，片段读取仍验证和解析全文。
独立基线中，16/32/64次追加快照保留2232623/8665631/34132991字节，增长接近平方；
对4 MiB来源做8次极小读取，仍读取并解析约33.6 MB。它们是当前代码夹具的资源观测，不是真实成员效果。

本批采用成熟的内容寻址与 Merkle 共享块模式、SQLite 索引和事务，以及上游 JSON Pointer 解析。
SQLite JSONB仍为 O(N)，增量 BLOB API本身也不验证片段；完整 IPLD/CAR 编码与传输栈不能直接替代现有任意 JSON
值域和所有权契约。因此只实现所需表示和访问适配器，不另造数据库、密码算法或标准定位解析器。
权威原件和阅读范围包括 IPLD、fs-verity、RFC9162、SQLite 官方文档、Python文档及官方精确版本源码；
本项目不声称实现IPLD编码、CT协议或内核文件系统功能。

归档以私有 SQLite 保存有类型、有版本的不可变块，复用不变内容和完整前缀目录。单块最多16 KiB，
目录扇出16，单次读取的已验证缓存最多128节点。读取核对实际消费的块、目录和长度信息，跳过无关内容。
新模块只有派生存储职责，不写任务事件、不放宽权限或质量规则；四文件控制核心预算保持1500行。
形成快照仍遍历当前原生数据；前部插入可能让后续分组移动，重写目录；没有普遍对数更新或无限资源保证。

协议和存储格式直接改为6，不提供旧库读取、迁移或兼容路径。`document`是绑定所有者的结构化根，
`selection`是所选子树的结构化承诺；都不是普通成果引用，也不是所返文本的直接SHA256。
免费读取明确返回 `integrity: selected`，只保证实际读取部分。免费 `audit-document` 遍历所有可达块，
验证类型、长度、标量编码和键序，返回 `integrity: full` 及另行命名的全文 `canonical_sha256`。
未读兄弟块损坏时，局部读取可以成功，完整审计必须失败。这是明确改变的保证范围，不能冒称与旧整文件扫描等价。
完整审计遍历图与内容，另有导航开销；核对巨大标量的规范编码时仍可能在内存中形成该标量。

## 并发初始化与成熟依赖

独立P4发现首版初始化窗口：12个新目录各8个并发冻结中，有12/96次因看见未完成的空归档而误报版本错误。
原失败源码与日志保留。修复采用成熟 filelock 4.2.6 的原生跨平台系统锁，初始化与既有格式准入完成后，
再进入正常SQLite图事务。锁有有限等待，禁用soft fallback，保留稳定私有锁路径；读和审计不创建或获取该锁。
既有空/坏归档不会自动清空重建。曾讨论的硬链接发布方案因SQLite别名与文件系统前提被否决，未实现。

官方精确wheel的SHA256为 `fd7d4fca497bf3e3d0945a13261f8e684f2aef12ce7cf76aef26e13bf7388b88`。
现有七个运行pin保持原值，仅新增此纯Python依赖，仍由pyproject单源生成哈希锁和诊断数据。
不全局安装、不在普通任务中静默下载。Doctor检查依赖与SQLite，真实数据文件系统的原生锁在首次写入时验证。

独立影响复验96/96自然并发成功，并确定性延迟首初始化者证明后来的写入者正确等待。
独立进程异常退出释放真实系统锁，稳定锁文件残留不阻止后续写入；这只是本机Unix证据，不冒称Windows执行。
原生ENOSYS、错误导入、soft lock替换和超时均安全拒绝；锁退出失败仍关闭SQLite连接，损坏元数据字节不变。
注入真实写入后的SQLite展示失败，效果仅执行一次，211字节回包保留真实任务、调用与已提交ok事实。
