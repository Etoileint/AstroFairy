## 根因与实现

旧接口只公开字段名，类型、枚举、范围留给模型猜测；处理器提供的拒绝原因又被回包抹掉。
本批用成熟 python-jsonschema 执行同一份公开输入模式，拒绝错参后才准入调用；可选纯预检处理独立的字节、路径和业务前提。
错误输入不进入处理器，不扣额度、不追加调用、不保存定义 blob。实际执行后的写入失败继续 unknown。
输出也有共同元数据契约和可选额外模式，不得用坏输出赚取 ok。

工具摘要只含名称、权限、简短说明和定义引用；完整模式通过 capabilities --name 按需读取。
历史调用绑定不可变定义，inspect TASK --contract REF 限本任务逐件读取，普通工作包和回执不嵌入模式正文。
动态注册须明确替换，公开注册表只读，外部修改原模式或返回副本不会改变执行规则。

采用明确的本地静态 2020-12 authoring profile，库负责实际验证及引用解析，项目不自造验证语言。
独立设计审查指出引用能把 const/examples 中的数据提升成执行模式，因此检查真实子模式及引用目标闭包；
另一个真实反例推翻了动态作用域去重方案，最终明确不接受动态引用/锚点及废弃关键词，保留静态引用和锚点。
未被引用的示例仍是数据。format 是标准注解，integer 接受 2.0，UTF-8 字节约束与语义前提单独说明。

公共 FairyError 保留安全纠正理由，生成的模式诊断只含公开模式位置和规则，不带被拒值或动态输入键。
超长、控制字符、非 JSON 等不可用公共诊断退为安全常量；任意异常原文不转发。
独立复验实际发现混合类型键会使诊断与事件编码不一致，现统一使用存储的 canonical 编码并检查整棵诊断树，
防止已写入后的错误卡在待观察状态。内部 host.model 标识及操作命名空间共用一个定义，拒绝扩展工具占用。

另以官方 RFC 6901 核实底层引用库对数组索引的宽松处理：本地 authoring profile 在解析前拒绝非规范数字式 token、
坏百分号与坏转义；对象同名非规范数值键也按保守限制拒绝。解析仍由库完成，不增加另一套 resolver。
编码后的字面百分号键、标准转义、静态锚点和递归引用保留正控；不是宣称无限制支持所有 2020-12 模式。

## 标准依赖与分发

原标准库-only 设计直接替换为完整成熟验证库。pyproject 是全量运行依赖 pin 单源；固定官方 PyPI release 原件
和 SHA256 清单驱动离线生成哈希锁、包内诊断数据，并由开发门拒绝漂移。没有 vendoring 分叉或自造安装器。
智能体用标准 venv/pip 在获准位置一次准备，再复用解释器；启动器不静默安装，不全局写包。
doctor/schema 在缺少依赖时仍能运行。标准技能目录仍为主要分发单元，源码复制/ZIP/可选 wheel 从同源构建。
协议与存储升为 3，不保留旧构造参数或旧数据库兼容路径，不迁移、不删除旧数据。
