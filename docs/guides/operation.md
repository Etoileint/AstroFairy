# Operation and verification

## State and interfaces

Use the installed skill's `scripts/fairy.py --home <approved-directory>` launcher.
`python -m astrofairy` is also available after installing the optional Python package.
Default home follows `ASTROFAIRY_HOME`, otherwise `~/.local/share/astrofairy`.
Task and call identifiers are generated by the runner. Keep the same home to resume.
The current development formats are store 10, protocol 11, stage packet 2 and receipt projection 2.
Old/unknown or malformed stores are refused before schema changes; choose a fresh approved home rather
than expecting migration or compatibility. An unsupported derived receipt is rebuilt only by explicit
`deliver --repair`.
Files generated by host tools belong in the workspace returned by `next`.
Prepare the [locked runtime dependencies](../../skills/fairy/references/runtime.md) once and reuse
that interpreter. `doctor` diagnoses interpreter/dependency/directory readiness without creating state. It does not test a
host's full permissions, durable storage guarantees or document-generation tools. Its search section keeps
dependency metadata, model-file presence and projection separate; presence is not `verified`, and default
doctor neither opens the task database nor hashes model bytes. `doctor --verify-search` stream-hashes the
six fixed model files without download or inference. It also executes an
in-memory SQLite materialized-CTE/window/callback/foreign-key probe through the store's connection setup.
An unsupported SQLite build refuses before a persistent home/database is touched; select a Python build
with those capabilities rather than changing an existing store or assuming a Python version proves them.
The host protocol is documented [with the skill](../../skills/fairy/references/host.md).
Delivery requires the vendored BagIt 1.9.0 wheel prepared from the skill's delivery lock; `doctor` reports
`delivery.ready`. The runner writes an explicit BagIt 1.0 header and regenerates the tag manifest, builds
in a private staging directory, performs full byte validation and publishes atomically to
`deliveries/<task>/<seq>/`. Manifest paths are converted from the library's host representation to
canonical POSIX identities before classification; every ancestor from the approved home through the
target, lock and staging is checked for symlinks/junctions without following them. An existing same-seq bag
is revalidated against the authoritative task, revision, seq, snapshot, receipt projection and member
digests, then reused without overwriting; a late fact creates a new seq directory. An invalid derived
export is refused by ordinary deliver with a repair route; `deliver TASK --repair --expected-seq S` builds
and validates a replacement, quarantines the old directory without deleting it, and publishes. Unsafe
path objects (`unsafe_delivery`) are never moved or followed. A repair failure between renames or after
publication reports its completed actions and quarantine identity. `files`
links point directly into the bag's `data/`; the bag root and receipt remain available for full
verification.

The database and exported files use private permissions on POSIX. Attachments and published snapshot members
retain their original bytes. File capture, hashing and export stream in 1 MiB chunks; a single content is
limited to 256 MiB and a task's captured unique content to 2 GiB, with explicit refusal on excess. UTF-8 is
explicit for text and protocol JSON; decode failures are visible.
`schema` renders accepted command fields from the parser table; unknown fields and duplicate JSON keys fail.
The initial `--spec` accepts goal, criteria, assumptions and required delivery roles. Omit criteria to select
the provisional defaults; supplied null and wrong types are rejected. A provisional agreement must be
refined with `revise` before complete delivery. Assumptions are part of the first created event, not a later
revision. Criteria declare `content`, `member` or `collection` scope; member and collection targets use
canonical relative paths, and collection targets may select an explicit subset.
The Python entry is `Workshop.start(request, spec={...}, resources=ResourcePolicy(...), effects=..., inputs=...)`.
Omitting resources uses the current defaults: warning after 128 work calls, final limit 1024. To configure
startup, use `start --resources FILE` with JSON such as `{"work_calls":256,"warning_calls":64}`.
Only these two fields are accepted; a missing warning defaults to the smaller of 128 and the chosen limit.
The policy and SHA256 fingerprint are frozen in the task. Changing the source file does not change that task,
and revise cannot replace it. next/inspect show resources usage, remaining calls, warning and exhaustion.
Warnings allow continued work. Tokens, fees and time remain host-managed; these counts do not measure them.
These defaults were exercised by the W05 resource calibration and frozen. `content.read` and `asset.read` are
free context operations; CLI document reads and `capabilities` catalog lookups are also free. Model requests,
asset search, mechanical checks, writes and captures remain counted. Free calls are visible in `free_calls`
but do not reduce `remaining_calls`. Questions have no cumulative quota, with one pending question at a time.
Choose reversible defaults and ask only consequential questions the materials cannot resolve.

`schema` also exports the typed implementation limits: command JSON 16 MiB, ordinary semantic text 1 MiB,
one workflow/guide body 16 MiB, one tool definition 3 MiB, one schema 1 MiB, content.read 24576 characters,
search pages up to 200, catalog pages up to 100, SQLite locks 30 seconds and each database backup deadline
300 seconds. These are separate from permissions and from real host token/time/cost.
Known SQLite runtime errors return nonzero JSON `storage_failed` with `sqlite_code`/`sqlite_name` when
available, without raw SQL or exception text. Preserve the store and inspect state before retrying;
this response does not automatically repair or recreate data. Version refusal remains `version`.

`complete`, `partial`, `failed`, `cancelled` are distinct results. An invocation success is not a quality result.
Check producer, scope, evidence and revision before interpreting a receipt.
On interruption, inspect pending calls before retrying. For a write with an explicitly pinned reconciler,
read that definition and invoke it with exactly `{call: ORIGINAL_ID}`. Its final authoritative observation
can settle the attempt while the original unknown/pending record remains. Other cases stay unresolved;
there is no arbitrary external recovery or absence-based retry. Verification uses ordinary read budget.
Current snapshot/revision checks remain separate. Inspect `execution_settled` and `execution_conflicts`;
`inspect_conflict` calls for honest investigation, without a force-clear path. Closed outcomes remain
historical. Late facts commit before the shared receipt refresh; export failure returns `committed=true`
with the operation identity and a `deliver` recovery command. Retry only the derived export, never the
recorded effect. Receipt seq identifies its snapshot, not a promise of zero projection lag or revocation
of already shared copies. The receipt is a stable historical projection; a changed installed checker
registry changes only the separate current assessment. If the current runtime lacks a required mechanical
checker, current acceptance reports `missing_checkers` and fails closed while history stays reusable.
`next` is a stage packet: it reports the action, an exact submission `payload` template, `acceptance`
conditions with the current checker assessment identity, a cheap `delivery` observation (`not_closed`,
`absent`, `unverified`, `unsafe`), recovery identity, the current snapshot, observed outputs, role
coverage, missing roles and unresolved failures. A closed task maps to `deliver`, `verify_delivery` or
`inspect_delivery`; `inspect_conflict` keeps precedence. A validated `deliver` result is evidence for that
operation, not a permanent delivered flag. Templates are generated from the current agreement and recorded outputs; they are not
evidence and do not authorize side effects. It may suggest `publish` and provide one `publish_candidate`.
Publication accepts the complete member list; a single file is simply a one-member snapshot.
`prepare-delivery TASK --members plan.json` records the full member plan before capturing anything, then
captures members, publishes the complete snapshot and runs applicable mechanical checks as separate
recorded actions. The plan and per-member progress are recoverable facts; a later call with only the
remaining subset still resumes the recorded full plan. Changing a recorded plan is rejected and requires
an explicit new task. It is resumable, not atomic, and never auto-passes semantic criteria. `inspect` shows
alternatives and historical snapshots.
Budget zero still permits existing reports, answers, publication and semantic review. It does not waive
required mechanical checks or allow a pass to erase an unresolved failure. Unreplaced failures block required
completion for the current agreement until a grounded current check or explicit semantic reassessment replaces
them; a new snapshot does not inherit collection-level passes.
Tool summaries are bounded (default 12, up to 100 with `--cursor`); `capabilities --name NAME` returns the
current declared value contract.
`inspect TASK --contract REF` reads one immutable historical definition recorded for that task, including
after closure. Ordinary work packets and receipts do not embed full schemas. Adapter authors use
the [tool contract](../../skills/fairy/references/tools.md), with actual schema validation before invocation.

CLI JSON stdout is capped at 24 KiB including newline and escaping. Oversized responses explicitly return
`deferred`, immutable `document`, owner scope, control metadata and counts. Use the free `read` command
with the same task and RFC 6901 pointer; concatenate returned text using `next_offset` until null.
The [host protocol](../../skills/fairy/references/host.md) defines exact fields and recovery rules.
Reads do not consume calls or change task state, even after closure. A deferred result keeps its original
exit status. Projection errors retain recovery identities; inspect before repeating committed work.
Full Python values, delivery receipts and source facts remain intact. Learning inputs now contain a
small locator for a complete source/history document, including aggregates larger than ordinary blobs.
Documents share immutable blocks; append snapshots reuse completed prefixes. Tiny and late fragments
verify only consumed blocks, with a bounded per-call cache. `selection` is a typed commitment, not a
plain-text checksum or task snapshot ref. Free `audit-document DOCUMENT [--task TASK]` checks all reachable
blocks and returns `canonical_sha256` for comparing complete reconstruction. A selected read can succeed
while an unread sibling is damaged; it does not certify whole-document health.
The private `documents.sqlite3` archive has a stable private `.init.lock` file for writer schema admission.
Never delete that lock while in use. Native locking is required; no soft fallback or automatic archive
reset occurs. Reads never create the lock. Snapshot construction, early insertions, full audits, event
replay, retained disk and total model context have separate costs. Keep the approved home and use only
needed sections; no automatic deletion or expiry is introduced.

## Recorded-state lifetime and recovery

Events, blobs, contracts, asset versions/status events and all document blocks remain retained.
Retirement affects discovery only; older task pins remain readable. Issued document handles can be
external roots, so document liveness is not inferred from current tasks. There is no automatic GC,
expiry, compaction policy or bounded disk guarantee. Deployment chooses backup cadence/capacity.

The agent can use these explicit administrative commands, with an existing approved parent directory:

```sh
python <skill>/scripts/fairy.py --home <data> audit-state
python <skill>/scripts/fairy.py --home <data> backup --out <new-backup-directory>
python <skill>/scripts/fairy.py verify-backup <backup-directory>
python <skill>/scripts/fairy.py restore <backup-directory> --out <new-home>
```

Backup uses native SQLite online backup: main first, then the append-only document archive. This is
one consistent main snapshot with a later document superset, including externally issued handles;
it is not one atomic timestamp across both files. Each image is closed/standalone before hashing.
A bounded completion manifest is written only after integrity and reference checks. Verify checks the
manifest, streamed file identities, full event/blob chains, registered references, exact asset metadata
and validation binding, and every retained document block. The archive audit shares visited-node work
across overlapping roots; individual audit-document still supplies its separate whole-text digest.
These explicit full audits may be expensive; ordinary task commands do not run them automatically.
Replay is the event-kind authority; unknown kinds are refused rather than silently omitted. Recovery
checks a maintained source's link to the child's exact source-document task and pre-decision sequence,
and checks captured delivery progress against retained bytes. Uncaptured planned members remain pending.

Recovery includes recorded attempts, original captured bytes, library and documents. It excludes
uncaptured workspace files, exported deliveries, environment/credentials and external-service state.
Retain those separately when needed. Restore never runs handlers, retries pending effects or overwrites
an existing home. It recreates workspace directories; deliver can regenerate captured outputs/receipts.
Historical immutable documents retain old locations as historical facts; next returns the restored
workspace. Pending/unknown calls still require normal investigation of actual effects.

A failed backup can leave a private partial directory without manifest. A failed restore retains
restore.pending; ordinary Store admission and doctor refuse readiness until investigated. Do not remove
it to bypass validation. Successful restoration removes its own marker last. Preserve failed directories
and original data; this system does not automatically repair or delete them. No power-failure test,
external authenticity, off-machine redundancy or whole-machine backup is implied by checksums/fsync.

Each single-event submit replies with that operation's committed seq. Another writer may advance the
task afterwards; refresh next before relying on current state. Feedback/report closedness comes from
the admitted transaction. Late facts commit and then attempt one shared post-commit export from a frozen
event snapshot; the response's committed seq and the separate `delivery.seq` may differ if another writer
advanced the stream before selection. Each admitted operation still verifies its complete history;
removing redundant post-commit replay is not a State checkpoint or a time bound.

## Assets

Candidate, trial, stable and retired are library states. Search projects the latest approved active head
in each personal/team family into a local LanceDB index. Retiring a head may expose a previously approved
version after the projection is refreshed. Package changes require a new immutable version. A stale
proposal must be rebased and revalidated.
Search fuses BM25 with ICU segmentation and exact-vector multilingual E5 results using per-path asset
ranks and weighted RRF (full-text 2:1); chunks cover metadata, structured applicability/dependencies/
invalidation, workflow steps and body. The fixed model profile records source/revision/file hashes,
tokenizer, prefixes, normalization and chunking. `assets search --refresh` explicitly downloads/verifies
the fixed revision and builds the projection; ordinary search passes a fixed local directory and never
downloads or starts another revision. A stale/missing index or model returns `search_not_ready` with the
refresh route, never an empty success. Results expose source generation,
profile and table version; filters use exact active heads and exclude candidates/retired versions.
The agent capability defaults to 8 and ordinary CLI pages to 50, both capped at 200 with `--cursor`/
`next_cursor`; `--scope` and `--kind` select a namespace/kind. The index is rebuildable;
SQLite asset events remain the authority. The [learning protocol](../../skills/fairy/references/learning.md)
defines proposals and local sharing.

Candidate validation checks structure and semantic fitness. It does not prove that a workflow is optimal;
actual use and feedback provide further evidence. Human preferences do not silently become team-wide rules.
Local sharing is implemented; account permissions, remote synchronization and background scheduling are not.
The host decides whether maintenance is worthwhile after delivery; `next` exposes `maintain`, `defer` and
`no_change` learning choices, and deferred items remain visible as todos. `python -m astrofairy todos`
lists unresolved deferred decisions across tasks without requiring a task id. It is not a daemon. A task
may fix adopted governance asset refs in its agreement; `python -m astrofairy governance --scope team`
lists adopted constraint assets with their structured applicability, dependencies and invalidation.
`governance_scope` in the start spec fixes those refs automatically; they are pinned through
`asset.read` and must be covered before complete, independent of search ranking.

## Development checks

The version source remains the single literal in `_version.py`, consumed by setuptools dynamic attr.
`dev/sync_metadata.py` reads it without executing that module, uses the pinned development packaging.Version
parser, and accepts exactly three release components, zero epoch and optional a/b/rc. Parsed integers
produce ASCII SemVer without leading zeros; standard equivalent PEP 440 spellings normalize to one target.
Post/dev/local, nonzero epochs and short/long release tuples refuse before any rendered consumer is written.
The source literal is preserved. This conversion covers the declared profile, with no host-upgrade guarantee
or support for arbitrary Python version expressions. See the [decision](../adr/0007-package-to-plugin-version-contract.md).

Run `python dev/check.py` in the development environment. It checks declared test surfaces, unittest suites,
Ruff, mypy, Markdown references and reported core/skill sizes. Size is reviewed without arbitrary hard caps.
Build the wheel and portable skill as separate checks.
The test pattern in `governance.toml` drives both file registration and standard unittest discovery. Every
matching file must own collected TestCases. Helpers use other names. Custom suite containers and
FunctionTestCase are unsupported; native suites are flattened once and the audited cases run in a new
standard TestSuite. Missing modules, empty suites, duplicate ids, foreign owners and import errors fail.
Decorated skips remain collected and visible. Each owner runs in its own process.
See the [validation record](../reports/initial-validation.md) for actual results and remaining boundaries.

Backup preserves captured record bytes exactly, including any credentials already present in them.
The environment/credential exclusion concerns uncaptured external files; it does not promise filtering
or redaction of captured events, blobs or documents. Treat backups with the same access control as records.
