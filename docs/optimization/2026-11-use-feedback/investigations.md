# 方案制定的调查任务与验收输入

本页给出必须回答的问题与完成证据，不预先采纳具体优化实现。问题来自维护者方向、
[反馈](findings.md)、[机制](mechanisms.json)与[预算](limits.json)，全部绑定 baseline.json。
没有原始模型轨迹的事项照样可开始可逆研究；确需真实环境的结论保持条件性。

## 全局验收要求

| ID | 下一阶段方案应满足的要求 | 必须提供的支持 |
|---|---|---|
| A01 | 普通成员自然委托，初始化、任务编号、检索和流程管理由 agent 承担 | 首次及后续正常任务轨迹；关键问题的数量、必要性和理解负担 |
| A02 | 普通任务必需信息及时到达执行者 | 逐阶段“必需→提供→读取/可得→实际动作”对照；主文加载不代签参考已读 |
| A03 | 正常多产物、修改、中断和必要问答可直接表达 | 原症状、正向路径、范围变化和部分交付的可运行证据 |
| A04 | 资源默认宽裕且可解释，保护边界只服务明确风险 | 每项保护对象、测量、范围、超限行为、恢复方式；无依据值重新论证 |
| A05 | 实际成果能核验，检查覆盖任务真实要求 | 成员/集合检查、材料依据、语义与机械来源、用户能理解的交付说明 |
| A06 | 学习可来自成功、错误、修订、反馈及重复结构，复用有净收益 | 保持/修订/退役/不变的分支；实际检索与适用判断；资产形成成本计入 |
| A07 | 核心职责稳定，扩展主要为数据/资产/适配器增长 | 删除测试、职责边界、单源与替换理由；不能仅靠拆文件躲行数 |
| A08 | 采用权威规范和成熟组件，准确声明适用范围 | 条款或 API→职责→实现→配置→验证映射，区分规范/建议/实践 |
| A09 | 保持权限、不可变身份、未知效果及诚实结果边界 | 原保护回归；不能以软化安全、吞错误、清失败换顺畅 |
| A10 | 得到足够验证后可以收敛，不扩大为重型平台或无限研究 | 有限代表性矩阵、首反馈/总时间/成本、剩余风险和停止判据 |

## 调查工作包

### T01 正常任务的信息路径与执行遵循

覆盖 UF01/UF02；先画首用及后续任务的信息流。逐项标出主文、阶段回包、必需协议、条件资料、
宿主环境和模型自主决定。包括要求转发、重复 next、资料续读、发布、检查、闭合和中断恢复。

比较域：当前入口；包含最小完整常规流程与工作示例的入口；运行器提供状态相关具体下一步；
必要的组合。不能只把全部参考复制进正文，也不能凭“写了必须”签收读取。

验证：同一宿主/模型/任务/附件和权限，保留原始提示、可见文件、工具调用及最终结果；
区分未激活、未读取、读取不全、理解错误、信息足够仍不遵循、环境缺失。对比首任务、续用、
修改、长资料与一次中断。记录完整性、管理调用、首个有效反馈、总耗时/费用和人类干预。

完成输入：明确的每阶段必需信息表；入口与回包职责；可证伪的遵循根因判断；格式/命名候选。
没有维护者原轨迹时，对原故障的归因保持未定，受控对照只证明其自身范围。

### T02 多产物协议与检查/交付身份

覆盖 UF03。先明确任务要求、成员身份、内容身份、交付快照、检查靶标、部分交付、历史版本。
以 A2A 多产物概念为结构参照，in-toto 的声明绑定和 BagIt 的齐全性/校验分离为局部对照；
直接采用格式/组件还是仅映射职责须有选择理由，不声称自动符合整套外部协议。

必须回答：同字节不同文件；路径/媒体类型/用途在判断中的角色；必交项如何匹配实际成员；
机械文件检查与集合语义检查；任务修订、内容变化、改名及新增无关成员后的判断适用性；
失败保留和有证据重评。局部结果复用须定义严格支持域，无法证明局部时按整体重验。

跨模块义务：库采用仍需确切候选及固定策略的验证，不能仅检查候选位于集合；所有历史成员
进入审计/备份/恢复引用；固定快照导出全部正式成果，支持中断重建、独立目录与回执版本，
防路径穿越、重复/大小写或文件目录碰撞、旧文件残留、用户文件与回执重名和并发混合。

完成输入：一个统一单/多成员模型、身份及完成不变量、源码影响图、有限验证矩阵。
开发无旧协议兼容包袱，但保留旧库和冻结报告；版本拒绝不得破坏旧数据。

### T03 全量资源策略与保护边界

覆盖 UF04 与全部 B01–B43。逐项输出保留/调整/合并/移除或仅作为监测项的理由，
分别注明技术事实、维护者策略和未测假设。内部块/缓存等参数不与任务次数统一调大。

必须比较：正常行为策略、软预警/可管理预算、最终硬保护；成本由宿主观测时采用真实量，
不把注册次数充当 token/账单。正常问答应由必要性和疲劳管理；调用额度须考虑内容读取、
多文件机械检查、失败修复和权威核对；不得自动无上限续额，也不要求普通用户配置预算。

检查字节/字符/节点/页/时间单位与所有消费者，尤其 MAX_CONTEXT_BYTES 的多用途耦合。
测代表性附件/手册规模、正常任务次数、峰值占用、竞争和备份增长；检查普通回包、
完整档案和模型上下文的不同成本。明确现实缺失的总量保护由谁提供，不能虚报已受控。

完成输入：有依据的分层预算策略、每项决策、调整权限与失败/取消/恢复行为；不先拍定新数字。

### T04 可发现、可读取、可判断的成熟检索

覆盖 UF05。先固定语料、相关性/不适用标签、索引字段、过滤规则及查询，不用同一批查询
反复调参后自评。资产元数据、正文、适用条件与返回证据分别设计。

比较域：当前基线、成熟全文/BM25、合适的多语言语义检索、混合与必要重排。SQLite FTS5、
Qdrant、LanceDB、pgvector 是职责/组件候选，并非依赖清单。逐一说明本地运行、安装、模型
来源/下载、CPU/内存、可选外部调用/数据去向和可维护性；不能默认新增账户或服务。

验证字段变化与算法变化分开；覆盖中文自然长句、短关键词、同义/中英表达、正文独有细节、
具体标识、近似但不适用、无合适方法、候选/退役/头版本与范围。记录 Recall@k、排序质量、
误用/拒用、端到端收益、索引构建/更新/重建成本，避免把近邻距离召回当作语义正确率。

召回候选数与最终送入上下文数量分别控制。权威资产为真源，索引为可重建派生物，采用/修订/
退役后的可见性有定义；旧片段可追溯对应内容。必需流程/约束不能依赖偶然 top-k 命中。

完成输入：有证据的默认检索路线、组件候选比较、模型/索引身份和生命周期、结果解释协议。

### T05 学习到实际复用的闭环

覆盖维护者的长期目标，超出仅纠错或重复任务。追踪成果/反馈→支持改善的信号→维护→
候选→验证→采用→发现→读取→适用判断→执行→新反馈，包括允许不变、拒用、修订和退役。

检查每个动作是正常路径中的明确步骤还是全靠模型自行想起；区分强制每任务维护与合理触发，
交付优先。事实、个人偏好、团队约束、方法/工具保持不同范围，避免临时事实晋升长期规则。
方法成熟以已执行正/反例和适用范围判断，使用次数/一次满意不能自动代替证据。

完成输入：有限且可执行的回流路径，正反例及无变化分支，端到端净收益计量，核心不增长说明。
真实长期使用、团队传播和人的进步属于后续现实证据，不作为本轮准备不能结束的理由。

### T06 质量、证据、权限与恢复不变量

横切 T01–T05。保留目标修订与不可变内容绑定、模型/工具来源分离、未决写入不盲重试、
迟到冲突、事务/序号、路径/权限、原件和可恢复导出。检查默认“相关语义＋非空”是否足以
引导具体任务准则；完整回执怎样帮助人理解内容组织，避免为记录而记录。

完成输入：必须保留的不变量和回归点、真实任务质量检查、审核者简明视图、失败恢复职责。
不得声称本地哈希提供外部认证，或恢复能重建未捕获环境/外部副作用。

### T07 便携分发、实际入口与首用

依据 S01/S03/S04/S19–S25，分别保留共享格式、五类宿主原件与已验证安装器版本的命令/前提。

覆盖首次环境、唯一技能身份、拷贝/ZIP/wheel/插件同源、原生名称、UI 提示和更新清理。
安装器复制成功、宿主发现、显式激活、自然选择、执行遵循和实际交付逐层取证。
普通目录与插件命名空间分开；不为了入口短而双份维护技能，不依赖通用标准未提供的别名字段。
另记录宿主一次调用的持续范围、后续轮次与上下文压缩后的可见性，不能把首次加载当作永久遵循。

完成输入：受支持宿主/安装模式的真实入口表及有限原生验证；超出实测平台准确声明待证。
不借机给所有宿主增加强制 hooks 或创建新的托管智能体平台。

### T08 核心职责与全量组合检查

逐个检查 mechanisms.json 的全部对象，并重新从愿景反推遗漏责任；历史台账是起点而不是
完备证明。每项说明必要职责、调用者负担、信息来源、成熟组件地板、失败发现与恢复和增长方式。
删除测试、单源、机制/策略边界均需实例；换行数/搬文件不构成架构优化。

完成输入：少量稳定职责、外围增长模型和各候选的必要性，跨 T01–T07 的冲突/依赖记录。
未发现新缺陷也可如实保持原设计，不为“全面”制造问题或新增器官。

### T09 证据、权威对照及方案收口

每一采纳或保留决定附适用来源、替代比较和可反驳验收；已有历史技术证据只在身份及语义
仍相同时复用。准备校验不等于方案通过，程序夹具不等于模型评测，维护者初试不等于团队试验。

完成输入：可实施且可审查的整体方案，含改变/保留/删除、顺序、资源成本、风险、验收、
文档同步及版本策略。独立主体先检方案，再检影响域实现；最终由维护者验收。

## 依赖顺序与有限验证

1. T01/T08 定义普通任务职责和信息需求；T06 同步固定不能损害的不变量。
2. T02/T03 分别确定交付模型与资源政策；T04/T05 研究可复用资产的发现与使用，互相提供输入。
3. T07 将新入口和协议接到实际安装模式；T09 汇总候选比较、影响域和验收计划。

每条路线至少包含原症状、正常正向、关键失败/恢复和一次组合路径。对方案没有决策价值的
重复测量停止；出现身份、内容或依赖变化时重验受影响范围，不要求全项目反复从零验证。

## 当前待补材料

- 维护者原始失败轨迹：宿主/模型/安装方式、原始提示/附件、实际读取和工具事件。
  它对归因 UF02 很有价值；未取得前可开展受控对照，但不能签原故障根因已证实。
- 中文/跨措辞检索标注集及任务质量准则：下一阶段固定，避免把旧微基准当作选型结论。
- 各宿主安装模式实测与可用嵌入/本地模型环境：决定支持承诺及默认路线前核实。

这些是显式调查义务，不是要求成员在日常使用中填写的配置或问卷，也不是本轮准备的阻塞项。
