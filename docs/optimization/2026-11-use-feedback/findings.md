# 五项反馈及其设计含义

本页只有五项反馈问题。原来的“加载后漏执行”和“主入口信息不足”合并为 UF02，
分别表示现象与根因假设，不重复统计。以下事实均绑定[当前基准](baseline.json)。
“源码事实”“局部程序观察”“维护者反馈”“待验证假设”是不同证据，不相互替代。

## UF01 调用入口与首次使用负担

- 维护者期望：安装后直接用“fairy，帮我……”或“星灵，帮我……”委托任务。
- 源码事实：`skills/astrofairy/SKILL.md` 的正式名称为 astrofairy，描述未声明这两个直接称呼；
  `agents/openai.yaml` 的默认提示也使用 astrofairy。CLI 文件 fairy.py 的名称不创建聊天入口。
- 尚未确认：该次使用的安装方式、实际发现名称、触发率和是否存在本地技能冲突。
- 调查方向：使用标准技能身份和宿主已有显式入口，优化自然语言发现；品牌、技能身份、
  运行器包名分别处理。唯一 fairy 入口是候选设计，尚未更名。
- 不应推导：简单更名就能保证所有宿主必然激活，或不同安装方式具有相同斜杠命令。
- 影响域：M01/M37–M41、C01/C06、T01/T07。主依据：S01/S03/S04。

## UF02 加载后执行不完整与必要信息装载

- 维护者报告：agent 已明确加载技能，但没有完全遵守；其他采用极简入口加外置资料的技能
  也出现过相似现象。尚无该次完整轨迹，不把描述扩展为所有模型的失败率。
- 源码事实：主文提供 Define/Produce/Check/Deliver 概述，首次任务要求另读 host.md；
  多数具体操作、记录和证据规则在参考文件或 schema/capabilities 查询中。
- 首要根因假设 H02：执行者只取得概述，未可靠取得常规任务必需的信息，就开始按默认习惯工作。
  主文加载、引用被打开、相关内容被读全、流程被执行必须分别观察。
- 备选解释：完整信息已进入上下文但仍漏执行；指令冲突或理解偏差；上下文丢失/压缩；
  宿主工具或环境不就绪；流程本身的管理成本过高。需要控制变量区分。
- 设计反思：核心小、用户省心和正文极短是三个目标。外置每次必需步骤会增加一次自主读取
  依赖；正文越长也不必然越可靠。需要比较最小完整入口、阶段必要信息直接提供及现有做法。
- 不应推导：读取一句“必须读参考”相当于实际加载；Matt 的个别转发包装等于所有技能必须很薄。
  S05 的信息层级、S08 的必需准则加载反例与 S02 的常规核心指令要求均需纳入。
- 影响域：M02/M05–M10/M15/M19/M31/M36，C01–C04，T01/T03/T05/T07。

## UF03 多文件正式交付限制

- 维护者报告：agent 认为最终成果只能有一个，其他文件以变通方式交付。
- 源码事实：`State.artifact` 取最后发布对象；有效检查绑定当前对象；`Workshop._delivery`
  导出该对象。发布历史和内容仍可保存多份。`State.outputs` 按内容 ref 建字典，同字节不同
  文件描述还存在折叠风险，需要在新的成员身份设计中明确处理。
- 程序观察 E01：实际运行器临时任务顺序发布 report.md、data.csv，前者再审被拒 stale，
  关闭后正式目录只有 data.csv 与 receipt.json；两份内容仍在存储中。程序中的语义 pass
  是受控夹具声明，不是业务验收。
- 调查方向：任务完成对应一个明确的多产物集合/快照；单文件自然成为一个成员。
  检查靶标、必交覆盖、跨文件一致性、完整导出、候选验证和恢复必须同时设计。
- 不应推导：只循环导出历史对象、强制全部打成 ZIP 或只让清单 JSON 通过 nonempty 即完成。
  历史对象可能包含中间稿，清单存在也不能证明成员内容已检。
- 影响域：M13–M18/M20/M23/M24/M27、N02/N05/N07、C01–C05、T02/T06。
  主依据：S09 的多产物模型、S10 的内容声明绑定、S11 的齐全性/校验分离，均不等于已符合整套标准。

## UF04 预算哲学与资源保护失配

- 维护者判断：资源并非如此紧张，不能为了轻量压缩正常工作；应有防意外失控的兜底。
- 源码事实见 limits.json：提问硬限、创建时调用预算、正文/核心规模门禁，以及文件、回包、
  字段、Schema、搜索和备份上限。各项作用域和单位不同，不能统一扩大或统一删除。
- 组合风险：多次内容分段、资产探索、多文件检查和写操作核对均可能消耗调用；同一常量被
  用于传输、语义字段和工具定义。低总次数不能证明低费用或短耗时。
- 边界事实：真实模型 token/费用与总体墙钟由宿主管理；库总量/重放成本无统一配额；
  注册处理器无通用执行截止时间。单 blob 上限不等于整个事件 payload 的总量上限。
- 调查方向：区分工作策略、可管理资源预算、故障保护和内部布局参数；在正常任务上测量
  假阳性阻断、峰值占用、恢复路径和真实费用，给出有依据的默认与最终边界。
- 不应推导：永久无限资源；自动反复放大硬限；放宽权限、路径包含、证据身份或未知写入保护。
- 影响域：所有运行路径，尤其 T03/T01/T02/T04/T05/T06。

## UF05 检索与经验实际复用不足

- 维护者疑问：当前检索可能过于基础，需要专业判断是否采用向量/其他成熟能力。
- 源码事实：当前活跃已采用头先选择，再对名称/摘要/实际标签做 casefold 后的字面 OR 匹配；
  按空格拆词，不检索正文、不处理语义同义词、无持久全文或向量索引。
- 程序观察 E02：受控已采用 PPT 资产搜 PPT 可得，搜“演示文稿”或不带空格的完整中文委托
  无结果；拆成 PPT 汇报则命中。这证明基础限制，不证明宿主一定不会改写查询。
- 历史证据 EH01：旧微基准仅 12 份材料/8 查询，语义检索未运行；全文对照同时改变字段与
  算法。不能当作向量无价值、全文必胜、生产召回率或最终后端选择的证据。
- 调查方向：在同语料、同相关性标准和同过滤条件下比较成熟全文、语义及混合路线；
  重排/适用判断与候选召回区分，覆盖正文、跨措辞、中文、版本/退役及重建成本。
- 不应推导：相似即可执行；必需流程可以依赖 top-k 检索；引入向量库自动完成学习系统；
  现有字面路线仅因依赖少就已满足长期目标。
- 影响域：M26–M34、C04/C05/C07、U01–U04、T04/T05。主依据：S12–S15。

## 横向反思：下一轮必须举一反三

这些是调查起点，不作为未经验证的新缺陷数：

| 风险假设 | 需要检查的连接 | 可反驳证据 |
|---|---|---|
| 易量化指标替代产品目标 | 行数/字节/次数与正常成果质量、首反馈、总负担 | 放宽或改变策略后并无收益，或现值有明确保护收益 |
| 关键步骤依赖模型自行想起 | 触发→建任务→取资料→登记→检查→交付→反馈/维护 | 实际轨迹证明足够信息到达且步骤稳定执行 |
| 协议抽象迫使正常工作绕行 | 多产物、变更、中断、必要澄清与任务分割 | 现有协议能自然表达且无需隐藏成果/另起任务规避限制 |
| 档案治理完备但复用链不闭合 | 保存→验证→发现→读取→适用→使用→反馈 | 有反例与净成本的重复任务结果支持收益 |
| 可审计记录被误当成质量保障 | 用户目标→检查要求→实际内容→组织依据→审核理解 | 验收能识别业务缺失，而非只认 complete/文件存在 |
| 分发格式或权威引用被误当成整体地板 | 标准条款→组件配置→接线→实际任务 | 对应责任逐项实测并准确限界 |

后续所有机制均需回答：谁承担该动作、必需信息如何到达、正常任务是否绕行、失败怎样
被察觉与恢复、成本落在哪里。原有证据身份、权限、副作用保护等价值不因这轮反思被一并撤销。
