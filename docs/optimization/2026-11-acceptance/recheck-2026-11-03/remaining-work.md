## A：交付权威绑定与流式保证（SPEC-02、REG-01）

一次设计补齐权威投影到实际目录的关系：实际 payload 集合必须与账本 snapshot **相等**，
不能只检查 Bag 自己列出了什么。回执所有影响审计的字段必须与同 seq 的真实投影一致，
不能只手列几个身份字段而漏掉约定、outcome、reviews 或未来新增字段。

沿用成熟 BagIt 完整校验；项目只承担权威关系规则。核对大文件使用既有流式摘要/原生 BLOB
接口，不为了加强校验回到整文件物化，也不用先查大小再豁免大文件检查。

复验：正确交付幂等成功；未选中成员、少成员、替换成员、换任务/seq、篡改约定/结果/审查后
即使重封成合法 Bag 也拒绝；8/32 MiB 至代表性大文件的校验内存不随文件大小双份增长。

## B：模型准备的真实 SDK 接线（ROOT-02）

采用实际支持固定 revision 和强制重取语义的成熟公开下载接口。先取得并核验原件，再交给
已修好的固定目录离线消费；不要通过 SDK 接受的任意 kwargs 推测底层已执行。
不要只补同名参数、追随 HEAD 或在哈希不符时修改锁来通过。

复验必须到实际下载接口：空缓存且远端 HEAD 与 pin 不同仍请求 pin；半下载可恢复；同长度
字节损坏能显式重取并核 SHA；普通查询无网络；准备失败可按同一入口恢复。可拦截网络传输
形成确定性反例，但至少验证真实调用链而非只 mock TextEmbedding 最外层。
保留缓存真实模型冒烟及准备进度，缺完整冷网络测量的部分如实说明。

## C：学习与治理的剩余连接（ROOT-04）

maintain 与其它决定一样成为可追溯事实，并关联来源/子任务；避免重复创建而源状态仍未决定。
待办由当前状态推导：defer 后解决不继续挂旧条目。提供跨会话/任务发现入口，成员不需记 TASK。
候选治理规则按明确范围从权威库确定，独立于 top-k 呈现给 host 判断；适用引用固定到约定，
不明条件明确提示，不靠 host 先知道正确 ref。

复验：来源/决定/child 链接一致且失败回滚；维护、暂缓、不变、解决、重开和新任务的待办发现；
必需规则不在语义短名单时仍被呈现；排除规则有明确依据，未知适用性交给 host；保留版本、
权限和精确候选策略。同步检索字段 profile，按影响重建投影并验证身份。
