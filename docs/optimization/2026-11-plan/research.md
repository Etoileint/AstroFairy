# 权威对照、备选与实际探针

本页解释选型理由；版本与原件身份见[sources.json](sources.json)及其引用的准备来源目录。
规范条款、组件功能、组件在本机能运行和端到端任务效果是四种不同结论。

## 1. 采用层次与行业地板

| 责任 | 依据/成熟实现 | 本方案采用方式 | 不据此声称 |
|---|---|---|---|
| 技能封装 | S01 Agent Skills，S04/S19–S22 宿主文档 | 直接遵循目录/frontmatter；按实际安装模式接宿主原生入口 | 各宿主都支持相同命令或能强制模型遵循 |
| 技能写作 | S02 官方建议、S05/S08 Matt 原件 | 常规必需信息就近完整提供；条件参考按需读；实际对照校正 | Matt 的薄转发是所有技能的规范 |
| 多产物结构 | S09 A2A Task.artifacts/Artifact.parts | 采用任务与多产物分离的语义，适配本地快照与权限 | 已实现整个 A2A 网络协议 |
| 内容声明 | S10 in-toto Statement | 采用确切内容摘要与声明靶标，保留来源/判断类型 | 本地摘要等于签名、外部证明或语义真实 |
| 文件交付 | S11 RFC8493，DS03 bagit-python | 直接生成/完整校验 BagIt payload/tag manifests，禁远程 fetch | 格式齐全自动代表任务完成；Informational RFC 是强制安全认证 |
| 解析和字段合同 | 既有 python-jsonschema、referencing、jsonpointer | 保留成熟解释器，领域字段/靶标由项目定义 | 自定义 Schema profile 等于支持全部 JSON Schema 特性 |
| 事务/内容/备份 | S16/S17 SQLite，DS04 Python blob API | 保留原生事务/备份；增量 BLOB I/O 替换大文件全量物化 | 跨两库同一时间戳或恢复外部副作用 |
| 全文/混合索引 | S14/DS01 LanceDB OSS | 直接采用 BM25/ICU/向量/RRF，原件与状态由主库管理 | 只有索引就有适用性、完整中文召回或永久最新 |
| 多语言嵌入 | DS02/DS08 FastEmbed，本地固定模型原件 | 采用成熟嵌入实现和公开支持的模型，记录完整 profile | 模型目录里有名字就代表语义质量已达标 |
| 跨平台数据目录/路径 | DS05 platformdirs、DS06 pathvalidate | 直接调用平台规则/路径验证，再做领域重复/包含校验 | 任意恶意宿主/文件系统竞态隔离 |

所有新增依赖须按原件和锁定构建流程进入分发，不能在用户任务中临时安装未固定最新包。
通用部件交给成熟实现；任务准则、检查有效性、权限/尝试、采用和回执是必要领域规则，
不能为了避免“自定义”把它们委托给不具备对应语义的数据库。

## 2. 信息组织的备选比较

| 备选 | 优点 | 拒绝或采用理由 |
|---|---|---|
| 继续四步概述并强化“必须读” | 文本最短、改动少 | 仍将必需信息获取交给第二次自主动作，不能消除已识别风险 |
| 所有参考整本内联 | 很少跳文件 | 大量运维/作者/异常规则占常规上下文，控制歧义和延迟仍未解决 |
| 只依赖脚本 next | 当前状态精确 | 模型必须先知道如何建立并进入流程；不能代替完整入口 |
| **完整常规主文＋当前工作包＋条件参考** | 首次可执行、阶段信息具体、低人工负担 | 采用；常规示例/结束条件在主文，载荷从合同生成，异常参考按条件读 |

这里没有把主文加长本身当作成功。实施对照必须保留实际加载和动作轨迹；根因解释服从证据。

## 3. 交付备选比较

| 备选 | 判断 |
|---|---|
| 多次 publish 后导出全部历史 | 无法区分当前正式成果与中间稿，检查范围仍错，拒绝 |
| 所有任务只交 ZIP | 传输可行，但不能解决成员检查和候选采用，拒绝作为内部模型 |
| 自定义目录＋手写校验清单 | 能表达领域信息，但已有 BagIt/实现可直接承担通用打包校验责任 |
| **不可变成员快照＋成熟 BagIt 导出** | 采用；内部表达检查语义，外部使用标准文件包，单文件亦走同一机制 |

PyPI 查询时 bagit 1.9.0 只有官方 sdist。本机隔离环境可构建纯 Python wheel；发布渠道须固定
构建链、原 sdist 摘要和输出 wheel，并测试真实安装。此构建不是已完成发布锁，也不能用一次
生成的 wheel 哈希充当所有机器都可重现的保证。

## 4. 检索后端比较与选择

| 路线 | 能力和代价 | 本轮决定 |
|---|---|---|
| 当前元数据字面扫描 | 依赖少，语义/正文覆盖不足 | 保留基线，替换默认实现 |
| SQLite FTS5 | 本地成熟、索引和 BM25 可用；中文 tokenizer 与语义另需解决 | 同语料全文对照，不单独承担默认语义目标 |
| Qdrant | 成熟过滤/混合/多阶段能力，服务端与本地模式有不同部署/并发边界 | 备选；不因名称含向量就选它，也不额外建设服务 |
| pgvector | 成熟 PostgreSQL 集成，全文＋向量可组合 | 本项目没有 PostgreSQL 运行前提，不增设数据库服务 |
| **LanceDB OSS** | 本地目录、原生全文/向量/RRF、ICU 内置分词、标准 Python wheel | 采用默认后端；需要独立验证事务投影接线与平台支持 |

初始使用精确向量查询，不为小库默认引入 ANN 的召回损失与调参。未来确有规模收益时，
可通过索引 profile 和同一协议选择原生近似索引，重建派生物，不增加任务内核分支。

FastEmbed 0.9.1 的实际支持目录与在线示例表并不完全相同，应以固定安装包和实际 API 为准。
首个默认模型 profile 选 **intfloat/multilingual-e5-large**，通过 FastEmbed 原生支持的
Qdrant ONNX 原件运行。原作者与转换发布者的材料见 DS14/DS15。选择依据是其成熟的多语言
检索训练与明确查询/文档协议，而非最小体积；目录声明 1024 维、约 2.24 GB、512 token。
实施须固定原作者 lineage、转换原件 revision/权重 SHA256、tokenizer，并遵守 `query: ` /
`passage: ` 前缀和归一化；不能把下载了同名模型当作转换完整性或效果已获验证。

也核对了 **minishlab/potion-multilingual-128M** 原作者材料（DS12/DS13）和实际支持目录。
这是 MIT 的 256 维多语言静态嵌入；模型本身不要求 512 token，而 FastEmbed 对应适配器的
配置边界需要单独对待。其速度优势不构成默认选择理由，先作为候选对照。W06 比较成熟全文、
默认神经嵌入和此静态候选；不达质量/启动/热查询门时依据证据调整固定 profile，而不是让成员
挑模型或静默退回字面检索。检索模型属于可替换策略，索引/任务接口不随之增加分支。

默认 E5 profile 通过 ONNX Runtime 执行；静态候选由 FastEmbed 的静态实现执行，不能混称。
任何型号均必须使用实际 tokenizer 保证切分覆盖，不能静默截掉后半部分。
索引和查询使用同一型号、revision、权重/词表哈希、归一化及前缀；不混用模型产生的向量。

## 5. 有限技术探针与限界

隔离环境位于本项目忽略的 `.evaluation/optimization-design/20261102/env`，与产品 `.venv` 分开。
本轮准备了 lancedb 0.41.0、fastembed 0.9.1、bagit 1.9.0。实际结果见 [component-probe.json](component-probe.json)。

探针检验 ICU 中文词项查询、混合/RRF 接线、范围预过滤、BagIt 同字节双成员与损坏拒绝，
以及原生 SQLite BLOB 分块写读。探针改用当前 `create_index(config=FTS(...))`，并以
`payload_entries()` 区分成果与 tag 文件；此前探针误用了总条目断言，已纠正，非产品失败。混合探针使用人为给定向量，**不是嵌入质量实验**。
模型目录检查不下载权重、不证明首启动延迟/内存或真实语义效果。当前环境还产生 CPU 特征探测
警告，不能将本机性能推为其他 ARM64 主机或 Windows/macOS 的结果。

## 6. 工程初值如何取得资格

每项资源初值在 decisions.json 中注明理由和 W05 校准义务。传输页、内部节点和诊断保护有
现成机制依据，可保留；问答、总调用、文件大小、Schema/正文/工具描述等要按正常任务和
异常边界实测。没有统一行业标准规定 AstroFairy 必须问几次或核心多少行，不能用标准名义
包装本项目策略。若正常任务被初值阻断或本机资源不支持，先校准配置/实现，再签分发就绪。
