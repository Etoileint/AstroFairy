# AstroFairy 整体优化方案

日期：2026-11-02。状态与独立设计检查见[设计验收](verification.md)。
本方案依据[已完成的准备](../2026-11-use-feedback/README.md)，覆盖五项合并反馈及全部既有机制。
维护者授权本轮正式制定方案，并要求业界规范和成熟实现作为地板。本轮交付设计，不改产品运行代码。

## 用一句话理解改动

保留现有可追溯任务循环，将它改造成**信息足够、步骤容易执行、多文件自然交付、资源宽裕、经验能被找到和正确使用**的工作机制。

成员仍然只需委托任务、提供材料和回答必要问题。常规流程直接出现在技能主文与当前工作包，
脚本承担确定的记录、捕获、检查、打包和状态判断；模型承担内容组织、语义判断和关键选择。
技能仍是合作式机制，不能保证模型绝对遵循；方案通过更完整的信息与更少的操作歧义降低遗漏。

## 主要决定

| 决定 | 采用方式 | 对成员的影响 |
|---|---|---|
| 唯一日常技能入口 `fairy` | 标准 name/目录与宿主原生调用；品牌及 Python 包仍 AstroFairy | 可自然称呼 fairy/星灵，也有明确的宿主显式入口 |
| 主技能提供完整常规闭环 | 必需步骤与一个有效示例直接放正文，条件参考保留 | 无需知道还应另找哪些协议 |
| 状态相关工作包 | 脚本返回下一步、所需资料、具体可提交参数及完成条件 | agent 少猜参数、少管理事务细节 |
| 一个交付快照容纳多文件 | 统一成员/内容身份、文件与集合检查 | PPT、数据表、讲稿等一起正式交付 |
| 采用 BagIt 标准目录包 | 由成熟 bagit-python 生成和校验，回执与文件分离 | 可直接打开文件，也能验证交付齐全与字节完整 |
| 重做资源政策 | 删除提问总次数、正文字节和核心行数硬门；其他边界按职责分层 | 正常工作不为小额度绕行，失控仍能停止和恢复 |
| 本地混合检索 | LanceDB OSS 的全文/向量/RRF，配合多语言本地嵌入组件 | 可按自然表达找到正文中的经验；无需开数据库服务或新账户 |
| 学习贯通到复用 | 状态提示与候选验证连接保存、发现、适用判断和实际反馈 | 好方法逐渐积累、修订、成熟和分享，允许不变与拒用 |

LanceDB/FastEmbed/模型和 BagIt 的确切版本、平台与接线须经实施验收；设计选择不等于已证明
语义召回提高或所有宿主均可用。当前技术探针与来源见[资料及探针](research.md)。
