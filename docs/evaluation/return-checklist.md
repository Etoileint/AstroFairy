# 回交材料与本会话验收清单

执行Agent完成可自主执行部分后，给出回交目录路径、简短结论和待证条件，本会话据此验收。
完成验证任务不等于P03–P07全部通过；本会话可以接受一份诚实、完整、仍含现场待证项的回交。

## 执行Agent必须提交

在独立return目录保存：

| 文件角色 | 内容 |
|---|---|
| submission.json | 按[结构](submission.schema.json)登记P03–P07结论与材料路径，product_accepted必须false |
| return_report | 范围、执行/未执行、主要结论、限界、发现、建议与需要本会话决定的事项 |
| runs_file | 每次任务原文/输入/路线/隔离、模型与工具身份、环境、日志与成果位置；脚本/模型/宿主/真人来源分别标注 |
| metrics_file | 明确时间端点、质量与成本原值；未知数据标未知，不换算不存在的token/费用 |
| coverage_file | V01–V17及S01–S16逐项新证据/继承证据/缺口；其余检查/对象按范围映射回链 |
| findings_file | 最小复现、预期/实际、发生条件、影响/严重度依据、原始证据、建议；无发现也明确写明范围 |
| sources_file | 官方/作者来源URL、版本/提交、UTC取得时间、SHA和实际阅读范围、适用机制/备选及比较结论 |
| human_trial_kit_file | 可直接交给成员的简短试用安排和观察表；没有真人也要完成准备 |
| human_evidence | 真实成员材料的相对路径；没有真实操作时为null，P05不得supported |
| evidence_inventory | 除清单自身和submission.json外，所引用报告/日志/输入/成果的path、bytes、sha256数组 |

角色对应文件名由执行者决定。JSON、CSV、JSONL、Markdown及成熟评测框架原生日志均可，避免二次转录丢失信息。
清单文件必须有真实内容：无发现可以零行数据加表头和声明，不能以待填写模板充当完成记录。
所有材料路径相对return目录，不允许路径穿越或符号链接。原生记录需要另存时复制授权的非敏感证据；
无法携出时记录精确取得条件和缺口，不填不存在的本地文件路径。人名/身份只保留取得授权且审查所需的最小信息。
不要将账户密钥、未获授权的客户材料或整份用户环境复制进回交包。

回交校验：

```sh
.venv/bin/python dev/check_validation_handoff.py --return .evaluation/product-validation/<run-id>/return
```

校验成功只说明版本、结构、路径和文件摘要相符，不证明实际执行、真人身份、来源权威或业务结论正确。
本会话还会执行下述实质验收。不得据此修改主工作状态或宣告整体产品验收。

校验完成后由协调执行者最后写`.evaluation/product-validation/LATEST_RETURN.json`，记录UTC时间、
相对该目录的submission路径及submission文件SHA256。索引只负责定位，不是接受结论；不覆盖已归档回交目录。
本会话读取这个索引即可定位结果，用户无需逐个传文件。

## 本会话的实质验收顺序

1. **对象身份**：重算156文件和所用载体，对照源码/包实际import来源；确认产品未被边测边改，新增资料未覆盖旧证据。
2. **证据发生**：从原始日志核任务/输入、实际命令/结果/时间与产物；抽取关键链路复现，不能仅读Agent摘要或评分。
3. **P03对照**：核真实模型而非预写协议；相同材料/工具、上下文隔离、评分污染、时间端点及关键失败。
   有矛盾时扩大影响域复验，不以同一作者自评直接覆盖独立判断。
4. **P04通道**：安装布局、原生发现/调用/模型任务、平台/更新/Office分别看；未测不认证。
5. **P05现场**：核真实成员/审核者操作来源；Agent说明、模拟反馈和沉默不能补齐现场证据。
6. **P06回流**：核新材料与反例、适用范围、维护/检索成本和来源；不把资产采用或单例成功等同长期净收益。
7. **P07覆盖与权威**：对照原愿景和范围映射，检最新适用官方/作者原文、成熟备选、描述与证据强度。
   既有技术闭合可继承；新效果必须有本次证据。不能用引用数量证明达到行业地板。
8. **发现处置**：判定真实问题、环境限制、夹具错误或已声明边界；重现真实问题后安排根因修复，再独立复验。
9. **范围决定**：给出接受回交/需补证/需返工及理由，明确允许的试用范围；用户最终决定产品接受。
   有限试用、技术验证、真实长期观察是不同结论，不要求伪造未来观察才能收工。

## 回交完成的最低条件

- 五条工作均有明确有据的判断；缺环境或真人时列具体缺口，其他可自主工作确已推进。
- 固定材料、每条路线真实成果、原始记录、指标和独立评价能相互追溯；未发生的动作不写成通过。
- 真人试用准备可直接使用；实际真人/长期证据没有时保留待证，不擅自对外联系。
- 新发现可复现、未被掩盖；主产品、依赖、预算、历史台账及用户全局环境未改。
- 基线和回交校验通过，或差异已明确解释并交回裁定。交接清单通过不等于产品通过。

## 最简回交消息

“回交目录：<path>。已执行：<范围>。主要结论：<结果>。发现：<编号/无>。
待证：<环境/真人/长期条件>。基线核对：<结果>。建议本会话：<验收/补证/修复事项>。”
