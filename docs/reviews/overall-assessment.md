## 架构处置

| 领域 | 判断 |
|---|---|
| 核心方向 | 保留宿主/运行器分工、明确协议与普通维护任务；先修连接及完成保证，不整体改成重型平台。 |
| 分发 | 保留Agent Skills共享目录和现有安装生态，宿主适配按需外围提供；不造统一安装器。 |
| 存储与版本 | 复用SQLite事务/备份和标准打包/版本工具；补准入与错误边界，不凭空引入完整迁移服务。 |
| 接口与检索 | 先补工具值契约及字面Unicode正确性；是否引入FTS/语义检索以任务相关性、成本和维护证据决定。 |
| 评测 | 修好现有测试发现并把已知反例纳入所属测试；需要持续模型评测时复用成熟Task/Dataset/Scorer/Log框架，放开发外围。 |
| 长期演化 | 经验、工作流与记录外置；保留/淘汰/增长政策和真实收益继续量测，不将行数预算当永远完备证明。 |

69个对象分别保存建议处置、问题依赖及最近Q08原始位置，见综合JSON的object_dispositions。
这些是本轮建议，不代签用户裁定；跨对象传播同一根因不另计缺陷。没有足够证据要求删掉整个核心或把项目改成重型平台。

## 仍未证明的效果

真实成员能否持续低负担使用、审核者耗时、原生模型显式/自动触发、其他系统、真实跨版本升级、Office渲染、
重复任务净收益与人的思路改善，都不能由现有有限样本签通过。R07一次两臂对照、R08空库也完成、R09受控迁移不会被改写成长期成功。
陌生模型已能重建一套PPT的组织依据；完整制作历史和包外证据另有取得条件。
后续评测应保留任务/模型/工具/环境身份，区分环境实际结果与代理自述，并按任务风险选择代码、模型和真人评价。
