# R04：任务协议、执行一致性与恢复

日期：2026-10-28。状态：主审取证、真实性复查及独立复验完成；三组发现未修复，FDP 分型保留，不宣称收敛。
产品基准：`22b7ece5d8388379f7b4bcaf47de4c047173cd9b`。范围见[R04 任务书](R04-brief.md)。

## 已取得的结论

当前机制能保守处理重要失败：执行前留下调用记录；中断后保留未决状态；
未决调用、待答问题和缺少必要检查都会阻止完整交付。检查确实绑定成果发布序号和任务修订，
不会仅因一次调用成功就把任务判断为成功。原始二进制输入、捕获及交付字节可保持一致。

但本轮确认三组接口保证尚未达到本项目契约及所比较成熟实践的相应地板：

1. `expected_seq` 并非所有命令都受同一约束：学习分支忽略它，检查分支存在预检与正式准入之间的竞争窗口。
2. 初始配置并非完整验证后才创建任务；非法假设可能报错却留下任务，部分错误类型还会被当作缺省值。
3. SQLite 故障没有进入 CLI 的 JSON 错误协议，调用者只能收到非零退出和异常堆栈。

三组均为本地词汇 **MAJOR / P2**，含义是接口或错误处理不一致，需要修复；
不是已经证明错误完整交付、历史丢失或安全边界被突破。生产机制保持冻结。
此前 R02-D01 的未知工具调用对账缺口仍未闭合；本轮增加中断前后的证据，不重复计作新发现。

## 状态与转移核对

当前状态是事件重放所得的组合状态，并非四个阶段枚举；产出、提问、调用和关闭并非一条互斥状态链。

| 前置状态/输入 | 准入与事件 | 后置状态及实际限制 |
|---|---|---|
| 无任务，start 合法 request/spec | 创建工作区，created，附件先存字节 | revision=1；CLI 假设通过 revise 追加，初始验证缺口见 D02 |
| 开放任务，request/invoke | 预算、effect、未决同 operation；invoked 先提交 | call=pending；效果与后续 observed 不处于同一数据库事务 |
| pending host.model，report | 同一 call、文本及输出名合法，observed | 只接受一次，origin=model；工具调用不能由该命令伪造回执 |
| 注册处理器返回/抛错 | 验证输出引用、写 observed | 正常 ok；write 异常 unknown；read 异常 failed；进程消失则 pending |
| 观察到本任务输出，publish | 输出引用和字节存在，published | 成果发布 seq 改变；即使相同 ref 再发布也要求新检查 |
| ask / answer | 最多一个待答，累计三次 ask；answer 可为主动更新 | answer 增 revision 并清问题；不是用户真实性认证 |
| revise | policy 不可改；user 变化需新 answered 序号；derived 可修订 | request 保留，spec 更新、revision 增；旧检查保留但不再适用 |
| review / check | 当前成果、revision、checker/producer、有效替代关系 | 冲突 fail 不被普通 pass 抹去；check 准入序号竞争见 D01 |
| close complete | 有成果、必要当前检查全 pass、无问题/未决调用 | 写 closed，停止新工作，再导出。工具成功本身不满足完成 |
| close partial / failed / cancelled | partial 必须有成果；其余不要求成果 | 可保留未决事实；不是把它们改成失败或回滚已发生动作 |
| 关闭后 late report / 正在执行的 tool 返回 / feedback | 允许记录观察与反馈 | outcome 不改；model/feedback 自动重导出，late tool 需 deliver |
| 导出失败、重开或 deliver | 读同一事件和内容重放 | closed 已存在；修正文件障碍后 deliver 恢复，无需重做成果 |

`next` 调度优先级为：已关闭、可完整关闭、预算耗尽、待答、未决调用、尚无成果、检查/修复。
这是建议包，不会强制宿主执行每一步；预算耗尽时仍可登记既有 model 结果与反馈。
提问上限和优先级的真实行为成本留 R03/R06/R07，不能仅凭转移表判定体验优秀。

| late-tool-observation | 处理器运行时关闭 cancelled，返回后 ledger seq=4；已有 receipt 仍 seq=3，deliver 后更新为4 |
| stale-sequence-learning / controls | learn 对 stale、0 仍成功建任务；正确 seq 对照也成功，证实不是拒绝任务状态的误读 |
| check-admission-interleave | 预检后另一连接 answer，旧 expected_seq=4 仍生成 revision=2 的检查；普通 stale request 对照被拒 |

## 发现及真实性复查

### R04-D01：乐观序号准入在分流路径不一致

- 分类：实现缺陷；主审按运行语义暂记概念级，FDP 分型保留见后文；MAJOR / P2。对象 A03/A04、M06/M11/M17/M19/M25/M36、C02/C03。
- 位置：`_contracts.py:134–154`；`_runtime.py:271–291`，尤其281–286；check:221–241。
- 依据：host:6 的 `expected_seq` 拒绝过期提交，以及事件溯源的同实体乐观并发实践。字段表允许所有命令携带它。
- 触发/预测：关闭任务 seq=2 后添加反馈至3，learn 携带2仍创建学习任务；
  check 预检读4后另一连接更新至5/revision2，仍会用旧 expected_seq 发起新版本检查。
- 第二起点：从控制流分支退出位置重新推导，增加 seq=0/正确 seq/普通 request 冲突对照；
  主审介入点试验及独立双进程屏障互证。检查仍绑定 revision2，因此不声称旧成果被错误通过。
- 根因/影响：共同准入分散在提前返回分支；有些路径缺失，有些只在效果开始前的非原子读取比较。
  宿主无法统一依赖该字段防止旧工作包继续执行，学习还可能增加不需要的新任务。
- 闭合方向：定义每个命令的比较对象和线性化点；在持久准入边界消费该前提，跨阶段检查保留目标绑定。
  修复后测 learn、check、invoke、普通命令的过期、竞争、无字段及正确字段控制。不靠取消字段承诺隐去缺陷。

### R04-D02：初始任务配置验证时机与缺省处理不一致

- 分类：实现缺陷；主审概念级登记保留；MAJOR / P2。对象 M05/M06/M07/M36、C01。
- 位置：`_cli.py:102–125`、`_runtime.py:80–102`，尤其 goal 的 `goal or request` 及 `if spec.get("assumptions")`。
- 依据：start spec 声明 goal、criteria、assumptions；严格验证应区分缺省值与错误类型，
  成熟模型验证可在创建状态前完成此工作。初始假设应实际进入任务协议，而非静默丢弃。
- 触发/预测：assumptions 为非空字符串，start 返回 invalid，却已持久创建不带假设的任务且响应不含该 id；
  goal=false/0/[] 或 assumptions=false/0/{} 则返回成功并忽略该字段。
- 第二起点：由命令事务边界转向类型/缺省分支，补正确字符串列表、非法列表元素及多个假值对照；
  独立复验另以混合类型列表重现已创建状态。
- 根因/影响：start 与追加初始 revise 分成两次写入；前置未验证完整请求，并用 truthiness 判断是否提供字段。
  非法初始请求可成为无直接返回 id 的残留任务，配置未按提交内容处理。尚未证明其会自动执行或错误完成。
- 闭合方向：先规范化并验证全部 spec，再一次提交初始任务语义；缺省/空值/错误类型逐字段明确。
  可保留 stdlib，也可比较严格模型验证组合；必须测报错无残留与合法输入保真。

### R04-D03：SQLite 运行错误逸出 CLI JSON 回包

- 分类：实现缺陷；主审概念级登记保留；MAJOR / P2。对象 M21/M36、C03。
- 位置：`_cli.py:162–173`；触发入口 `_store.py:21–46/78–79`。
- 依据：CLI 的机器可读 JSON 输出契约；Python 官方异常族确认 sqlite3.Error 不属于已捕获的 OSError 等类型。
- 触发/预测：指定普通损坏数据库运行 next，非零退出但 stdout 为空、stderr 含异常堆栈；
  调用方不能按现有 error/message JSON 协议获取失败类型。
- 第二起点：不依赖“非 SQLite 文件”，独立主体在合法 SQLite 中构造不匹配 events 表，
  inspect 触发 OperationalError 同样逸出。该受控损坏不是声称产品会自行生成错表。
- 根因/影响：基础设施异常族未在机器接口边界映射。失败是可见的，不能将其写成静默成功、数据库恢复失败或历史已丢失。
- 闭合方向：在边界规范化已知数据库运行错误，保留非零状态和可诊断类别；不要删除/重建数据库冒充恢复。
  分别验证损坏、忙锁、不可写/完整性及异常映射时的保密和可恢复性。

### 边界、候选与撤回

| 编号 | 换起点复查及结论 | 去向 |
|---|---|---|
| R02-D01（复用） | 效果前/后进程退出、重开、重试/报告及完整关闭均复查；公开协议仍不能对 pending/unknown 工具调用登记核对结果。同任务继续完成的可用性责任尚未裁定；已有诚实停止/partial 路径 | NOTE/P2 候选保持开放，R14/R16 明确承诺及受控对账/交接方案，不降低未知门 |
| R04-N01 | 迟到 tool 有 ledger 而 receipt 需手动 deliver；并发旧导出可覆盖新投影。换以 feedback 自动重导出对照，确认不是事件丢失；导出失败也可重建 | NOTE/P2，R05/R15 明确 receipt 是有 seq 的快照、消费时如何核新鲜度；如承诺最新投影需另设计同步 |
| R04-N02 | 篡改 blob/中段可检出，尾删可留有效前缀。换以信任边界原文核对，已明确宿主可改库/哈希且无外部认证，撤回“完整防篡改被攻破”指控 | NOTE/P3，R14 必须保留边界，不把链完整性称为独立审计认证 |
| R04-X01 | 非 UTF-8 内容不能 content.read，不代表二进制原件丢失；从 capture→store→export 字节路径重推，原字节相同 | 撤回编码保真缺陷；文档/渲染能力待 R05/R06 |
| R04-X02 | close 关闭后新工作被拒不代表迟到结果被抹去；原 model call 可 report，既有 tool 可 observed | 撤回生命周期丢结果指控；投影限制归 N01 |
| R04-X03 | 本地 canonical 与 JCS 排序/数值不同，但当前没有 JCS 承诺；检查本地重放和分享消费者后不能仅凭函数名定违规 | 撤回 JCS 不合规指控；跨语言标准化若成为要求，R09/R12 再选成熟 JCS 实现 |
| R04-X04 | SQLite/replace 的成熟原语不等于整套部署具备掉电和多文件事务证明；只有进程退出及可重建投影证据 | 不作实测断电通过或断言断电必丢数据；R10/R14 留证据责任 |
