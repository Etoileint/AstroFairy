## 取证安排

先固定合成材料和模拟用户回复，再让新主体仅从冻结skill入口完成任务，尚不读源码或旧复核结论。
依次观察模糊但可推进的任务、普通语言改变交付方向、确有关键缺口的任务。
关键问题由主审按预存回复扮演用户回答，不让执行模型自行生成“用户回答”。
完整保留实际命令、失败、首条说明、进度、交付内容及时间观察；中途未记录部分如实声明。
这些是实际模型使用样本，模拟用户不是团队真人，不据此推断所有成员都易用或已学会更好工作。

之后主审和独立主体分别复核协议、准则/回答/修订、下一步调度、取消/部分交付/重开与诊断。
独立主体先报告从源码新推的候选，再比较主审发现；不读旧报告、主审探针或当前报告草稿。
权威对比使用原作者HCI指导、官方人机交互指南、宿主/Agent Skills入口契约及成熟持久化/中断实现。
只有取得正文并实际读入的部分进入判据；启发式、产品文档、机械结果、模型观察和真人效果分别标记。

## 七项判断

| 检查 | 关注 |
|---|---|
| R03-01 | 管理员准备与成员委托分开；无需成员操作内部编号/JSON |
| R03-02 | 可自行调查或可逆默认直接推进，材料事实忠实保存 |
| R03-03 | 必要问题简单、有推荐；答案到达前不做依赖决定 |
| R03-04 | 方法、任务管理、工具发现、协议修错由宿主承担 |
| R03-05 | 普通语言纠正和变更进入目标/准则/当前成果，版本关系可追溯 |
| R03-06 | 记录首反馈与有用进度，不把执行者日志时间冒充真实UI送达时间 |
| R03-07 | 用户能拿到成果与下一步；取消、部分交付与续作不依赖用户排错 |
