## 本轮已经证成什么

冻结技能符合本轮取得的 **Agent Skills 共享格式要求**。目录迁移和 ZIP 隔离运行通过，
脚本没有隐含的父仓库或第三方 Python 运行依赖。入口、首次协议及恢复/学习引用有清楚落点。
这些是格式、静态结构与机械执行的结论，不能推导每个宿主已经正确发现、自动选择、调用或更新。

厂商扩展静态核对未见冲突：共享 frontmatter 只使用标准字段，Claude 插件/市场清单位于外围，
OpenAI UI 元数据位于 `agents/openai.yaml`。原生插件校验器、UI 展示及完整宿主行为仍待证。

本轮使用官方参考实现，同时独立核对规范。反例表明：损坏正文链接、移除运行器或破坏 UI YAML，
参考校验器仍可能通过，因此它不是完整技能质量认证工具。

## 描述、触发与按需资料

入口第 3 行把“有检查的委托成果”作为主要用途；第 9 行将组织、默认取舍和关键问题交给宿主。
它是一条任务交付流程，不要求一个行业一个技能。描述广泛不自动违反“聚焦一个工作”的写作指导；
仍须用实际宿主检查误触发、漏触发及与专业技能的配合。

| 文本用例 | 预期路线与依据 | 本轮证据类型 |
|---|---|---|
| 根据附件制作内部演示文稿 | 属文件成果委托；专业制作技能可作为工具/子流程 | 描述与用户目标对照，非实际激活 |
| 对比三份方案并给出建议报告 | 属分析/计划成果 | 文本对照 |
| 将已有成果改给另一类受众，保留数字 | 属修订 | 文本对照 |
| 再完成一次上次的同类工作 | 属重复任务 | 文本对照，不证明已学到成熟流程 |
| 解释一个概念或编程语法 | 普通问答可以直接回答，不必建任务 | 描述负例；未观测模型是否误用 |
| 同时有 PDF/PPT 等专业技能 | 星灵可负责组织，专业技能负责提取/制作；也可能由宿主直接选专业技能 | 竞争/组合待实测，不自制打分表充当路由观测 |
| 用户明确提及 astrofairy | 表达用户选用意图；各宿主原生选择方式不同 | 公开文本边界成立；不保证所有自然语言提及都变成原生强制调用 |

资料路由为：首次任务读 `references/host.md`；修订、检查冲突、失败或中断读 `review.md`；
交付后有反馈或改进依据时才读 `learning.md`。三个目标存在、引用不越界、协议步骤可执行。
学习不作为首次交付前置；候选验证和收据模型并非规范强制机制，它们另由产品机制轮次审查。

## 迁移、ZIP 与校验器反例

主审脚本位于本机 `.evaluation/reviews/R11/probe_contracts.py`。参考校验阶段允许使用现有开发依赖；
**两个运行器子进程均为 `python -I -S -B`**，不会借用 site-packages 或可编辑安装。
路径含空格和中文，工作目录为空目录，数据位于安装目录之外。

| 试验 | 结果 | 限制 |
|---|---|---|
| 固定官方源码 validate | 标准源目录、迁移目录、ZIP 解包目录均返回空错误列表 | 只证明该校验范围 |
| 已安装 0.1.1 CLI validate | 冻结目录通过 | 不掩盖与官方源码身份差异 |
| 原始目录迁移 | doctor 不创建状态；start→捕获真实二进制→publish→check→合成语义 review→close 成功 | 语义 pass 明确为夹具，不是用户质量评价 |
| ZIP 迁移 | 同样完整交付，含 `0x00/0xff/CRLF` 的成果字节保持一致 | 没有实际文档引擎或原生应用 |
| ZIP 内容 | 18 项，无重复；每项与规范源字节一致，保留许可证，无测试/缓存或私有安装清单 | 本轮未重建或安装 wheel，留 R12 |
| 元数据生成 | plugin、marketplace、随包 LICENSE 均与冻结生成器结果一致；当前工作树 check 也通过 | 生成一致性不是原生插件校验 |

六个变体只存在于忽略试验目录：

| 变体 | 固定官方参考校验器结果 | 说明 |
|---|---|---|
| 去掉 description | 拒绝 | 必需字段检查发生 |
| name 与目录不一致 | 拒绝 | 命名检查发生 |
| 增加 Claude 专用 disable-model-invocation 字段 | 拒绝 | 厂商可接受字段不自动成为共享字段 |
| 添加不存在的正文引用 | 仍通过 | 不检查正文引用 |
| 删除全部 scripts | 仍通过 | 不检查承诺的运行器是否存在 |
| 将 agents/openai.yaml 改成损坏 YAML | 仍通过 | 不检查厂商 UI 元数据 |

后三项是校验器覆盖边界，不是实际产品包含这些损坏。本项目已有链接、打包隔离、元数据检查承担不同责任；
不因参考工具范围有限就另造一个共享标准解释器，也不凭三种负例推定现有门已覆盖所有故障。
