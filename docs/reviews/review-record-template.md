# 正式轮次记录与取证要求

这是 AstroFairy 的执行记录格式，不重新定义 FDP。每轮复制字段并填写实际证据，避免空模板冒充已执行。
报告按 `Rxx-主题.md` 放在本工作区并在轮次索引中登记；新增索引在第一轮实际产生时创建。

## 开场声明

- 轮次、被审提交及工作树差异、对象编号、R/Q/V 编号、纳入与排除范围。
- 程序归属：架构及机制设计为 FDP 方法内验证特化；源码、行为与效果另有相应证据。
- 执行者：实际承担本轮取证的主体；独立复验者：新上下文、不携带主审假设的主体；裁决者：用户。
- 方法版本与原件身份：正文、载体、复核协议的版本/摘要；未装载原件不得宣称完整执行方法。
- 比较前提：任务、宿主、数据规模、权限、质量目标、资源和长期要求。

## 权威来源逐条记录

| 字段 | 内容要求 |
|---|---|
| 来源身份 | 标准发布者、原作者或项目官方维护者；从官方入口核对仓库/文档归属 |
| 版本 | 标准版次、发布 tag 或 commit；可变文档需取得时间、响应目标和内容摘要 |
| 定位 | 条款、标题、源码文件/符号/行号、原始试验及产物位置 |
| 实际读入 | 正文、源码、目录或摘要的真实读取范围；标明未读与访问限制 |
| 支持主张 | 原文实际支持什么；规范义务、设计建议、实现自述及实验结论分别标记 |
| 适用条件 | 对应哪个对象、职责和运行前提；不适用某条标准需有依据，不能免除整个对象的对标义务 |
| 材料保存 | URL、摘要和本机原件引用；可变 URL 的原件可取得性限制如实说明 |

二手文章、搜索摘要和模型记忆只提供查找线索。官方项目的营销性自述不能独立证明效果优于当前方案。
需要标准全文才能判断的条款，保持待证；不得据目录页、预览或付费页推断全文合规。
每个合理候选的实际比较范围先声明，对该范围完整阅读；整个上游仓库未读时不写成已全部研究。

## 逐对象对标记录

每个对象独立填 Q01–Q08，允许共同证据被引用，但保留该对象的适用分析。

- 其职责、必要性与设计承诺。
- 权威规范、成熟设计和实现的合理候选；采用、排除及继续调查的理由。
- 比较维度及最低保证；运行前提和不可比差异。
- 当前实现定位、结构分析、负例和可复现实验。
- 组合后的实际保证与成本，关联 C 对象。
- 结论：达到适用地板 / 在列明维度超过 / 未达到 / 待证；说明证据强度。
- 处置：保留、直接复用、组合适配、替换、简化或重设计；记录影响及验证路径。

上述状态不由引用数量、组件知名度、代码行数或自有实现的偏好决定。
通用能力优先比较直接复用或组合成熟机制；自行重写需说明无法适配之处或可验证优势，并证明关键地板没有降低。
轻量是需要同时实现的产品目标，不能充当基础保证不足的理由。
没有发现明确正式标准，也要完成成熟实现调查和设计比较，再报告已查范围及剩余未知。

## 检查项与发现

逐项检查记录：编号、结论、证据、范围和待补义务。
每条发现记录：编号、概念级/成文级、严重度、处置优先级、位置、触发条件、预期与实际、
违反依据、攻击起点、可证伪预测、根因、影响、闭合建议、关联对象和检查项。

严重度采用 FDP 所引用的本地五级词汇：BLOCKER、CRITICAL、MAJOR、MINOR、NOTE。
本项目原 P0–P3 是处置优先级，两者逐条给出影响依据和映射，不声称该词汇已获外部标准条款认证。
FDP 方法原件提供设计纪律；外部行业的地板仍需各自权威源证成。

发现真实性复查记录替代攻击起点、重新推导和结果。误判保留撤回理由，不删除历史。
独立复验记录隔离声明、实际输入集合、逐项意见或无冲突声明、存疑与冲突裁决。

## 收口与后续

- 覆盖：被审对象、逐行读入范围、未读/未测、场景、外部依据版本与未决前提。
- 结论：哪些主张成立、被否定或待证；以证据支持的范围表达，不推断永久正确。
- 状态：完成取证、需补证、需修复/重设计或有条件接受；未闭合概念问题逐条移交，不能宣称已收敛。
- 义务去向：剩余事项的负责方、落位和下一步，注明关联轮次与影响范围。
- 独立复验与用户裁决：记录实际发生情况；未发生就保持相应状态。
- 修复单独安排，保留前后证据，按影响范围重验并更新说明和台账。

正式复核、修复和外部发布各按当时实际授权执行，准备或取证完成不自动扩大权限。
不会把母项目 Issue 追踪地址带入本仓；仅有复核授权时不创建外部 Issue、不发送消息、不提交或推送。
