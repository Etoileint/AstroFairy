# AstroFairy 0.1.0a2 · Alpha

2026-11-03 · [English](#english) · [简体中文](#简体中文)

## English

This prerelease improves everyday task delegation, multi-file delivery and reuse of validated methods.
The maintainer authorized committing and publishing after the scoped independent technical review.
The original review records remain bound to their source snapshots; release authorization does not
declare every host, platform or long-term evaluation objective complete.

### Changes

- The standard skill name and installation folder are `fairy`. Essential steps and a working example
  are in the main skill; stage packets supply the next action, required information and completion conditions.
- One formal delivery snapshot can contain multiple files and roles. BagIt 1.0 packages bind their
  exact payload set and complete receipt to the authoritative task record. Capture and verification stream bytes.
- Resource policy is explicit and fixed per task. Defaults warn at 128 work calls and stop at 1024;
  clarification has no cumulative question limit. These are local safeguards, not token, time or currency limits.
- Adopted assets use local LanceDB BM25/ICU plus multilingual E5 vectors and weighted RRF. Explicit
  preparation downloads a fixed model revision and verifies declared SHA256 identities; ordinary queries
  use the fixed local cache. The first preparation needs network access, disk space and substantial memory.
- Learning records maintain/defer/no_change decisions, links maintenance tasks atomically, discovers
  unresolved deferrals across sessions and fixes selected governance references to task agreements.
  Governance candidates are independent of semantic top-k; applicability still needs host judgment.
- Backup audits typed source/child links and captured delivery progress. A restored interrupted delivery
  can resume from captured members. Source distributions retain locked vendor inputs and rebuild the same skill.

### Install and data

Use the [README installation instructions](../../README.md#install). The fixed release command is:

```sh
npx skills@1.7.4 add https://github.com/Etoileint/AstroFairy/tree/v0.1.0a2 --skill fairy --copy
```

Requirements: Python 3.12+, prepared hash-locked runtime/delivery/search dependencies, a capable SQLite
build and a host with local command/file access. The verified installer requires Node.js 22.20.0+;
manual copying needs no Node.js. Five project-level installer targets were exercised; native application
discovery, invocation and managed plugin updates remain separate support questions.

Artifacts: `fairy.zip`, `astrofairy-0.1.0a2-py3-none-any.whl`, `astrofairy-0.1.0a2.tar.gz`, and `SHA256SUMS`.
The ZIP contains the standalone `fairy/` skill folder. Runtime preparation is still required. Optional
plugin metadata uses version `0.1.0-alpha.2`. This release does not publish to PyPI or a plugin marketplace.

Protocol/store format is **10**, compared with 7 in `0.1.0a1`. There is no development-store migration or
backward compatibility. Keep old data/backups separately and use an approved fresh home for this version.
The renamed skill is a clean new entry, without an old-name alias; remove obsolete installed copies as appropriate.

### Validation and limits

The final technical check collected 195 runtime tests: 194 passed and the real-model test was skipped
by default, then passed separately with the prepared real E5 cache. All 20 development tests passed,
including building/extracting the sdist, validating locked inputs and rebuilding the byte-identical skill.
Typing, style, skill structure, metadata, lock/provenance consistency and document checks passed.
The [independent acceptance](../optimization/2026-11-acceptance/final-2026-11-03/README.md) records
fault injection, concurrency, receipt tampering, streaming allocation, governance and recovery evidence.

Real-user usability, host adherence, broad Windows/macOS support, native plugin lifecycle and long-term
team learning benefits remain unproven. Local model preparation/loading consumes meaningful resources;
the controlled evaluation observed about 4 GiB peak process memory. Cached smoke tests do not establish
cold download timing. Semantic quality and suitability remain model/host judgments. Retained history,
replay and disk use can grow; there is no automatic garbage collection or guaranteed exactly-once external effect.

## 简体中文

本次预发布改进日常任务委托、多文件交付与经过验证的方法复用。
维护者在有范围的独立技术复验后授权提交发布；原复核继续绑定其源码基准，
发布决定不等于所有宿主、平台或长期效果验证完成。

### 主要变化

- 标准技能名和安装目录统一为 `fairy`。主文直接提供必要闭环与有效示例，阶段包给出下一步、
  所需材料和完成条件。
- 正式快照可以交付多个文件和角色。BagIt 1.0 的实际文件集合与完整回执绑定权威任务记录，
  捕获及校验使用流式处理。
- 资源政策随任务固定，默认128次工作调用预警、1024次停止；必要澄清没有累计次数上限。
  这些是本地兜底，不是模型 token、总耗时或真实费用预算。
- 资产发现采用本地 LanceDB BM25/ICU、多语言 E5 向量及加权 RRF。显式准备固定模型版本并核验
  声明的 SHA256，普通查询使用固定本地缓存；首次准备需要网络、磁盘和较多内存。
- 学习维护、暂缓、不变决定可追溯；维护子任务与源决定原子关联，待办可跨任务和会话发现。
  治理候选独立于检索短名单，选定引用固定到约定，语义适用性仍由宿主判断。
- 备份审计学习来源/子任务链接和捕获进度；恢复后的中断交付可继续使用已捕获成员。
  源码分发物保留锁定原件，并能重建字节一致的技能包。

### 安装与数据

见[中文 README](../../README.zh-CN.md#安装)。固定本版：

```sh
npx skills@1.7.4 add https://github.com/Etoileint/AstroFairy/tree/v0.1.0a2 --skill fairy --copy
```

需要 Python 3.12+、准备好的哈希锁定运行/交付/检索依赖、具备所需能力的 SQLite 和可执行本地
命令、访问文件的宿主。已验证安装器要求 Node.js 22.20.0+，手动复制无需 Node.js。
五个目标通过了项目级复制安装；原生应用发现、调用和托管插件更新须分别判断。

附件为 `fairy.zip`、`astrofairy-0.1.0a2-py3-none-any.whl`、`astrofairy-0.1.0a2.tar.gz` 和
`SHA256SUMS`。ZIP 内含独立 `fairy/` 技能目录，运行前仍需准备依赖。插件元数据版本为

协议及存储格式为 **10**，旧公开版 `0.1.0a1` 为7。开发期不迁移、不兼容旧数据库；

可按实际安装情况清理过时的技能副本。

### 验证与边界

最终技术检查收集195项运行测试：194项通过，默认跳过的真实模型测试另行使用 E5 缓存通过；
20项开发测试通过，包含源码包解压、锁定原件核验和技能包逐字节重建。类型、风格、技能格式、
元数据、锁与来源及文档检查通过。[独立验收](../optimization/2026-11-acceptance/final-2026-11-03/README.md)
记录了失败注入、并发、回执篡改、流式分配量、治理及恢复证据。

真人易用性、宿主遵循率、广泛 Windows/macOS 支持、原生插件生命周期及长期团队学习收益仍待观察。
本地模型准备和加载需要实际资源，受控评测观察到约4 GiB进程峰值内存；缓存冒烟不证明冷下载时长。
语义质量与方法适用性仍依赖模型和宿主。历史、重放及磁盘占用可以增长，没有自动垃圾回收，
也不保证外部动作恰好执行一次。
