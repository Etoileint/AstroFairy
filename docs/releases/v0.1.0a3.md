# AstroFairy 0.1.0a3 · Alpha

2026-11-08 · [English](#english) · [简体中文](#简体中文)

## English

This prerelease fixes platform dependency preparation and makes delivery failures recoverable without
losing committed work. The maintainer accepted the scoped repairs and authorized publication with
the remaining integration and real-user observations recorded below.

### Changes

- Runtime and search hash locks preserve target-environment conditions, including Windows dependencies.
  `doctor` checks the required SQLite capabilities and readiness without creating a task home.
- `assets prepare` explicitly prepares the pinned model and verifies all six consumed files.
  Explicit `assets search --refresh` also prepares an empty library; ordinary discovery does not
  silently download weights. Dependency readiness, verified model bytes and usable inference remain
  separate observations.
- Windows BagIt payload classification respects native filesystem paths while preserving canonical
  POSIX member names. Unsafe directory redirections are refused before following or moving targets;
  native junction tests cover four delivery boundaries and ordinary/repair paths.
- Task closure and late observations retain their committed facts when export fails. Responses expose
  the delivery state, completed filesystem progress and a precise recovery command. Explicit repair
  validates the replacement and preserves the quarantined old directory.
- Receipt projection 2 uses recorded facts and checker identities. Historical receipt bytes stay
  stable across restarts and current-checker changes; current assessment is separate. Transaction
  cleanup preserves the original failure, and unknown calls retain their investigation identity.

### Install and data

See the [README](../../README.md#install). Pin this release with the verified installer:

```sh
npx skills@1.7.4 add https://github.com/Etoileint/AstroFairy/tree/v0.1.0a3 --skill fairy --copy
```

Python 3.12+, the bundled runtime/delivery locks and a capable SQLite build are required. Local hybrid
search additionally needs its search lock and explicit model preparation. The verified installer
requires Node.js 22.20.0+; manual copying needs no Node.js. Hosts supply the model and task tools.

Artifacts: `fairy.zip`, `astrofairy-0.1.0a3-py3-none-any.whl`, `astrofairy-0.1.0a3.tar.gz`, `SHA256SUMS`.
The skill name remains `fairy`; optional plugin metadata is `0.1.0-alpha.3`. This release does not
publish to PyPI or a plugin marketplace.

Protocol **11**, stage packet **2**, receipt projection **2**, store **10**, document archive **1**.
The previous release used protocol 10. Development stores have no migration or backward-compatibility
promise: retain old data/backups separately and use an approved fresh home for this version.

### Validation and remaining observations

The [independent Windows acceptance](../audit/changes/2026-11-08_windows-round2-acceptance.md) verifies
the original evidence for the repaired runtime. Linux aarch64 local checks and Linux x86_64/Windows
x64 hosted CI passed; the Windows developer machine used CPython 3.12.16 built by conda-forge,
SQLite 3.54.1 and Windows build 26100. Its 255 runtime tests included 248 passes and seven explicit
skips: three POSIX permission tests, two file-symlink privilege tests and two real-model tests.
All 42 development tests passed. Junction tests actually ran without requiring file-symlink privileges.
Source/wheel/sdist/ZIP tasks ran outside the checkout; installed origins and upstream BagIt validation
were checked. Counts overlap and do not measure independent coverage.

The release workflow separately checks the final versioned commit, builds from its Git archive,
compares distributed files, verifies isolated installation and publishes checksums. Its exact source
commit and final CI links are recorded in the GitHub release body.

Cold download/interruption recovery, independent-process model-cache contention, Windows real E5
inference, the full current skills-CLI installation matrix and real-host preparation/recovery/learning
remain follow-up observations. Cached Linux E5 evidence does not establish Windows inference or cold
download behavior. macOS and other interpreters/architectures are not certified by these runs.
Real-user usability, host adherence and long-term learning benefits still need field evidence.
Model preparation has substantial disk/memory cost; there is no automatic history garbage collection,
host sandbox or guarantee of exactly-once external effects. These limits remain explicit in this Alpha.

- 运行及检索哈希锁保留目标环境条件，包括Windows依赖。`doctor`实测所需SQLite能力和准备状态，
  不创建任务数据目录。

- Windows BagIt分类兼顾原生路径与POSIX成员名；拒绝不安全目录重定向，不跟随或移动外部目标。
  原生junction用例覆盖四个交付边界以及ordinary/repair路径。
- 关闭任务或晚到观察提交后，即使导出失败，事实仍保留。回包给出交付状态、实际文件系统进度和准确
